# 第3回「情報デザイン・UI/UXとWebマーケティング戦略」（11/10）

# **1. 情報のデザインとアーキテクチャ**

## **1-1. インフォメーションデザインと情報構造化の基礎**

### **【インフォメーションデザイン（Information Design）】**

受け手が情報をスムーズに理解し、迷わず的確な行動をとれるように、**情報を分かりやすく整理・視覚化・伝達する設計手法**。

単なる見た目の装飾ではなく、「情報の伝わりやすさ」そのものを論理的に最適化します。

### **【情報アーキテクチャ（IA: Information Architecture）】**

Webサイト内の膨大なコンテンツを分類・整理し、**目的の情報へ迷わず辿り着けるようにWebサイト全体の情報構造・導線を論理的に設計する技術や思想**。

建築の設計図のようにサイトの骨格を定義します。

<aside>
💡

**階層の深さと幅のバランス（ディープ vs ワイド）**

階層構造を設計する際は、縦の深さ（ディープ）と横の広さ（ワイド）の**適切なバランスを取ること**が鉄則です。どちらも極端になると使いやすさを損ないます。

- **ディープ構造（深すぎる）：** 1画面の選択肢は減るが、クリック回数が増えて現在地を見失いやすくなる。
- **ワイド構造（浅すぎる）：** クリック回数は減るが、1画面の選択肢が多すぎて探すのに迷ってしまう。
- **設計の目安（3クリックルール）：** 両極端を避け、トップページから**3回以内のクリック**で目的の情報へ辿り着ける深さに設計するのが理想とされます。
</aside>

## **1-2. 代表的な情報構造モデル**

![出典：[https://seesaw-design.co.jp/service/uiux-structure/](https://seesaw-design.co.jp/service/uiux-structure/)](https://seesaw-design.co.jp/wp-content/themes/seesaw/assets/images/service/uiux-structure/02.webp)

出典：[https://seesaw-design.co.jp/service/uiux-structure/](https://seesaw-design.co.jp/service/uiux-structure/)

| 情報構造モデル | 構造の特徴 | メリット・デメリット |
| --- | --- | --- |
| **階層型（ツリー型）** | トップページを頂点としてカテゴリごとに下位階層へ枝分かれする最も基本的な構造。 | **⭕️** 構造が明確で全体像を把握しやすい。<br>❌ 階層が深すぎるとクリック数が増加。 |
| **直線型** | ページを1本道（直線的）に順序立てて進ませる構造。 | **⭕️** 次のステップが明確で迷わない。<br>❌ 自由な移動・スキップには不向き。 |
| **ファセット型** | 単一の階層ではなく、「価格」「色」「サイズ」など複数の属性で横断的に絞り込む構造。 | **⭕️** 条件の組み合わせで目的の品を素早く特定できる。<br>❌ サイトの全体像を把握しにくく、条件・属性の管理が複雑。 |
| **ネットワーク型** | 上下関係を持たず、関連情報同士が網の目のようにリンクで相互に結ばれた構造。 | **⭕️** 自由に回遊できる。<br>❌ 現在地を見失いやすい（迷子になりやすい）。 |
| **ハブ＆スポーク型** | 拠点ページ（ハブ）から各コンテンツ（スポーク）へ放射状に分岐し、必ずハブへ戻る構造。 | **⭕️** 現在地を見失いにくく機能切替が容易。<br>❌ スポーク間の直接移動には不向き。 |

## **1-3. サイト設計の主要ドキュメント**

Webサイト制作では、関係者間で全体像や各画面の構成を共有するため、制作フェーズに応じた設計ドキュメントを作成します。

| 設計ドキュメント | 形式・主な作成ツール | 役割と特徴 |
| --- | --- | --- |
| **サイトマップ<br>（Site Map）** | ツリー図、階層図 | **Webサイト全体のページ構成や階層関係を図式化・視覚化した全体構成図。** 全体のボリュームやカテゴリの包含関係を俯瞰・一覧するために用います。 |
| **ディレクトリマップ<br>（Directory Map）** | 表計算ツール<br>（Excel、Googleスプレッドシート等） | **全ページのURL、タイトル、階層構造、ファイル名、概要などを一覧表にした管理リスト。** 制作進行管理やサーバー上のファイル構成の基準となります。 |
| **ワイヤーフレーム<br>（Wireframe）** | 単色の線画・枠線<br>（Figma、XD、手書き等） | **各ページのレイアウト、コンテンツ配置、情報の優先順位を示した画面の設計図（骨組み）。**色や装飾を決める前段階で各画面ごとに作成します。 |
| **モックアップ<br>（Mockup）** | 静止画像デザインカンプ<br>（Figma、Photoshop等） | ワイヤーフレームに配色・タイポグラフィ・写真などのビジュアルデザインを適用した**「完成予想の静止画」**。 |
| **プロトタイプ<br>（Prototype）** | インタラクティブな試作品<br>（Figmaプロトタイプ等） | 実際にボタンクリックや画面遷移などの**動作・操作感（インタラクション）を検証できる動的な試作品**。 |

<aside>
💡

**設計ドキュメントの使い分け**

ワイヤーフレームは**「各ページのレイアウト・骨組み」**を設計するドキュメント。

**サイト全体のコンテンツやページ構成を一覧・俯瞰して確認・管理できる**のは、サイトマップやディレクトリマップです。

</aside>

## **1-4. Webサイトの目的別分類と設計の要点**

Webサイトは、発注者が達成したいビジネスゴールによってターゲットや求められる構造が大きく異なります。

### **【目的別の代表的なWebサイト】**

| サイト種別 | 主な目的・ゴール | 特徴と設計の要点 |
| --- | --- | --- |
| **コーポレートサイト<br>（企業サイト）** | **信頼性・認知度の向上** | 企業の事業内容、企業理念、会社概要、IR情報、採用情報などを発信し、取引先や社会からの信頼を獲得する。 |
| **サービス / ブランドサイト** | **認知拡大・ブランディング<br>資料請求・商談獲得** | 特定の製品やサービス、ブランドの世界観を伝え、見込み顧客の獲得や問い合わせにつなげる。 |
| **ECサイト** | **商品の直接販売・決済** | 商品の見つけやすさ（ファセット検索）と、カゴ落ち（購入前の離脱）を防ぐスムーズな決済フロー（直線型構造）が重要。 |
| **ランディングページ<br>（LP）** | **特定アクション（CV）の獲得<br>（問い合わせ・購入・登録等）** | 広告等からの流入を受け止める縦長1ページのサイト。他ページへのリンクを排し、1つの行動（購入・登録等）に直結させる。 |
| **オウンドメディア** | **検索流入の獲得・見込み顧客の育成** | 企業が自社で保有・運営するメディア（ブログ等）。有益な情報を継続発信し、検索流入と長期的な顧客関係を築く。 |

# **2. UI（ユーザーインターフェース）設計とナビゲーション体系**

## **2-1. Webナビゲーションの分類**

ユーザーがWebサイト内で迷子にならず、目的のページへスムーズに辿り着けるように誘導するための道しるべです。

| ナビゲーション種別 | 配置場所 | 役割と特徴 |
| --- | --- | --- |
| **グローバルナビゲーション<br>（GNav）** | ページ上部（全ページ共通） | サイト内の全ページに共通して設置される最重要メニュー。サイトの主要なカテゴリへの移動手段を提供します。 |
| **ローカルナビゲーション<br>（LNav）** | サイドバーなど | 現在閲覧しているカテゴリ内、または同一階層内の詳細ページ群へ移動するためのメニュー。 |
| **パンくずリスト<br>（Breadcrumb）** | メインコンテンツの上部 | **トップページから現在地までの経路を、ツリー構造を持ったハイパーリンクの一覧として示すもの。** |
| **フッターナビゲーション** | ページ最下部 | サイトマップ、利用規約、プライバシーポリシー、著作権表示、お問い合わせなど、補助的だが重要なリンクを網羅します。 |
| **ユーティリティナビゲーション** | ヘッダーの右上など目立たない補助位置 | コンテンツ閲覧とは直接関係ない便利機能リンク（ログイン、サイト内検索、言語切替等）。 |
| **コンテキストナビゲーション** | 本文内、記事の下部など | 文脈に応じたリンク（「関連記事」「この商品を買った人はこちらもチェック」等）。 |

<aside>
💡

**ナビゲーションの実装ポイント**

- **パンくずリストの設計：** 童話『ヘンゼルとグレーテル』に由来する。「現在地の把握」「上位階層への移動」「クローラーの巡回支援（SEO向上）」を担います。HTMLでは `<nav>` と `<ol>`（順序付きリスト）で実装します。
- **`<nav>` 要素の役割：** HTML5の **`<nav>`** 要素は、**グローバルナビゲーション**などの主要なナビゲーションに使用します（著作権表記や外部広告リンクには使用しません）。
</aside>

---

## **2-2. 代表的なUIコンポーネントと操作設計**

ユーザーが直感的に操作できるよう、Webページでは機能や用途に応じたUIコンポーネントを適切に使い分けます。

| UIコンポーネント | 役割・定義 |
| --- | --- |
| **CTAボタン**<br>（Call to Action） | ユーザーに「購入」「資料請求」などの**目標行動を促す最重要ボタン**。 |
| **モーダルウィンドウ** | 画面前面に表示され、**閉じるまで親画面の操作を制限（ブロック）する**ダイアログ。 |
| **カルーセル** | 限られた領域で、**複数の画像やバナーを横方向に切り替え・スライド表示する**UI。 |
| **プログレスバー** | フォーム入力やダウンロードの**進捗状況（進行度）を視覚的に表示する**UI。 |
| **アコーディオン** | 見出しのクリックで、**隠れた詳細コンテンツを上下に開閉（伸縮）させる**UI。 |
| **タブメニュー** | 同一エリア内で、**見出しを切り替えて表示内容を瞬時に切り替える**UI。 |
| **マイクロコピー** | ボタンや入力欄の周囲に添える、**ユーザーの不安解消や行動を促す極めて短い補足テキスト**。 |

# **3. UX（ユーザーエクスペリエンス）とユーザビリティ**

## **3-1. UIとUXの違い・包括関係**

UIはユーザーと製品をつなぐ「接点」であり、UXはその利用を通じて得られる「体験の総体」を指します。

| 概念 | 正式名称 | 意味と役割 |
| --- | --- | --- |
| **UI** | User Interface<br>（ユーザーインターフェース） | ユーザーと製品が接する**「接点・道具・見た目」**。<br>ボタン、画面レイアウト、文字、配色、操作部など。 |
| **UX** | User Experience<br>（ユーザーエクスペリエンス） | 製品やサービスの利用を通じてユーザーが得る**「体験・印象・感情・満足感の総体」**。 |

<aside>
💡

**UIとUXの関係性**

優れたUIは、優れたUXを生み出すための重要な構成要素です。ただし、**「UIが美しい ＝ 優れたUX」とは限りません**。

どれだけデザインが美麗でも、表示速度が極端に遅かったり、注文手続きでエラーばかり出るサイトは悪いUXとなります。

</aside>

---

## **3-2. ユーザビリティの定義と基本特性**

ユーザビリティは絶対的なものではなく、「誰が（ユーザー）」「何のために（目標）」「どのような環境で（物理・社会的環境）」使うかによって評価が変化します。

<aside>
💡

**国際規格 ISO 9241-11 によるユーザビリティの定義**

**「特定の利用状況において、特定のユーザーによって、ある製品が、指定された目標を達成するために用いられる際の、有効さ、効率、及び満足度の度合い。」**

</aside>

### **【ユーザビリティを構成する3大要素】**

1. **有効さ（Effectiveness）：** ユーザーが目標を正確に、完全に達成できている度合い（目的が達成できたか）。
2. **効率（Efficiency）：** 目標を達成するために費やした資源・労力・時間と、得られた結果との関係（手早く簡単にできたか）。
3. **満足度（Satisfaction）：** 製品を使用したことによる快適さや好意的な態度の度合い（気持ちよく使えたか）。

### **【ヤコブ・ニールセンの「ユーザビリティの5大特性」】**

Webユーザビリティの第一人者であるヤコブ・ニールセン博士が提唱した使いやすさの5つの品質属性です。

1. **学習しやすさ：** 初めて使うユーザーでも、すぐに基本操作を習得できること。
2. **効率性：** 一度操作を覚えたら、手際よく作業を進められること。
3. **記憶しやすさ：** しばらく使っていなかったユーザーでも、迷わず操作を思い出せること。
4. **エラー発生率の低さ：** エラーを起こしにくく、起こしても迅速に回復できること。
5. **主観的満足度：** 使っていて心地よく、満足できること。

## **3-3. 代表的なユーザビリティ評価手法**

Webサイトやシステムの使いやすさを検証・改善するために、対象者や目的に応じた評価手法を実施します。

| 評価手法 | 概要と特徴 | メリットと活用場面 |
| --- | --- | --- |
| **ユーザビリティテスト<br>（行動観察法）** | **実際のターゲットユーザー（被験者）にタスクを与えて操作してもらい、その行動や様子を観察・分析する手法。** | 開発者の思い込みを排し、実際のユーザーが画面のどこで迷い、つまずいたかを直接発見できます。 |
| **思考発話法<br>（シンクアラウド）** | **ユーザビリティテスト中、被験者に「考えていることや疑問」を声に出しながら操作してもらう手法。** | 操作行動の背景にある**内面的な思考プロセスや心理**を正確に把握できます。 |
| **ヒューリスティック評価** | **専門家（エキスパート）が、確立された経験則（ヒューリスティクス）やガイドラインに照らして評価する手法。** | 被験者を集めるコストや時間をかけずに、開発初期から短期間・低コストで迅速に課題を洗い出せます。 |

## **3-4. 人間中心設計（HCD）とUXデザインの設計ツール**

### **【人間中心設計（HCD: Human-Centered Design）】**

システムやWebサイトを開発する際、企業の都合や技術先行ではなく、**「実際に使う人間（ユーザー）のニーズや使いやすさ」に主眼を置く設計思想・プロセス**。調査、設計（プロトタイプ）、評価を反復（イテレーション）して品質を高めます。

### **【ペルソナ（Persona）】**

![出典：[https://www.microwave-creative.co.jp/column/detail/how-to-create-personas/](https://www.microwave-creative.co.jp/column/detail/how-to-create-personas/)](https://www.microwave-creative.co.jp/cms/image/97caef146ce249c8ac262bf7f509177f/81d03d4d583348078d95c98e21ce3411/img_column_how-to-create-personas_01.webp)

出典：[https://www.microwave-creative.co.jp/column/detail/how-to-create-personas/](https://www.microwave-creative.co.jp/column/detail/how-to-create-personas/)

ターゲット顧客層の中から設定する、**実在するかのような「架空の典型的なユーザー像」**（氏名、年齢、職業、ライフスタイル、ITリテラシー、悩み、目標など）。

開発チーム間での認識のブレを防ぎます。

### **【カスタマージャーニーマップ（CJM: Customer Journey Map）】**

![出典：[https://www.transcosmos-cotra.jp/what-is-a-customer-journey](https://www.transcosmos-cotra.jp/what-is-a-customer-journey)](https://www.transcosmos-cotra.jp/wp-content/uploads/2026/10/Areas-for-Improvement-Identified-Through-the-Customer-Journey-Map-1-768x401.png.webp)

出典：[https://www.transcosmos-cotra.jp/what-is-a-customer-journey](https://www.transcosmos-cotra.jp/what-is-a-customer-journey)

ペルソナが商品やサービスを認知し、情報収集、比較検討、購入を経てファン化に至るまでの**一連のプロセスを時系列で可視化した図**。

ユーザーの不安・不満（ペインポイント）を特定し改善策を立案します。

# **4. Webマーケティング戦略と基本フレームワーク**

## **4-1. マーケティング分析のフレームワーク**

### **【3C分析（ミクロ環境分析）】**

自社を取り巻く市場環境を3つの視点から客観的に把握するフレームワーク。

![出典：[https://jajaaan.co.jp/web-marketing/framework/3c/](https://jajaaan.co.jp/web-marketing/framework/3c/)](https://jajaaan-co-jp.exactdn.com/wp-content/uploads/2020/01/3c-1024x633.jpg?strip=all&lossy=1&quality=90&ssl=1)

出典：[https://jajaaan.co.jp/web-marketing/framework/3c/](https://jajaaan.co.jp/web-marketing/framework/3c/)

| 要素（3つのC） | 対象 | 主な分析内容・着眼点 |
| --- | --- | --- |
| **Customer** | 市場・顧客 | 顧客ニーズ、市場規模、購買行動の動向。 |
| **Competitor** | 競合 | 競合企業の強み、弱み、市場シェア、戦略。 |
| **Company** | 自社 | 自社の強み（USP: 独自の強み）、弱み、保有リソース。 |

### **【SWOT分析（内部・外部環境分析）】**

自社の内部環境と外部環境を4つの要素に整理・クロス分析するフレームワーク。

![出典：[https://www.hrbrain.jp/media/human-resources-management/swot-analysis](https://www.hrbrain.jp/media/human-resources-management/swot-analysis)](https://images.ctfassets.net/9n4tetpf9eny/5OLJJB2QjHrossJL5izGhz/23ce2cc3296e08cd0a374189ea3d8468/CMD-3848-02-1280x720-20250108.png?fit=fill&w=1260&q=50&fm=avif)

出典：[https://www.hrbrain.jp/media/human-resources-management/swot-analysis](https://www.hrbrain.jp/media/human-resources-management/swot-analysis)

| 区分 | 要素（4つのS/W/O/T） | 主な内容・着眼点 |
| --- | --- | --- |
| **内部環境** | **Strengths：**強み | 競合に勝る自社の特長や技術力。 |
|  | **Weaknesses：**弱み | 自社の課題や不足しているリソース。 |
| **外部環境** | **Opportunities：**機会 | 法改正、市場拡大、トレンドなどの追い風。 |
|  | **Threats：**脅威 | 新規参入、景気後退、技術の陳腐化などの逆風。 |

### **【STP分析（ターゲットと立ち位置の決定）】**

自社の商品やWebサイトが「誰に」「どのような価値を」提供するかを定めるフレームワーク。

![出典：[https://accel-japan.com/columns/column104/](https://accel-japan.com/columns/column104/)](https://image.accel-japan.com/wordpress-uploads/2025/11/04103108/column104_1.jpg)

出典：[https://accel-japan.com/columns/column104/](https://accel-japan.com/columns/column104/)

| 分析段階 | 役割 | 主な内容・着眼点 |
| --- | --- | --- |
| **Segmentation** | 市場細分化 | 年齢、性別、地域、行動特性などで市場を切り分ける。 |
| **Targeting** | 標的市場の選定 | 細分化した市場の中から、自社が狙うターゲットを絞り込む。 |
| **Positioning** | 立ち位置の確立 | 競合他社と比較し、自社独自のポジション（差別化ポイント）を築く。 |

### **【4P分析（売り手視点） vs 4C分析（買い手視点）】**

マーケティングミックスを設計する際、企業の視点（4P）と顧客の視点（4C）を対比させて検討するフレームワーク。

![出典：[https://bruceclay.jpn.com/column/4c-analysic/](https://bruceclay.jpn.com/column/4c-analysic/)](https://bruceclay.jpn.com/wp-content/uploads/2025/04/4c4p.png)

出典：[https://bruceclay.jpn.com/column/4c-analysic/](https://bruceclay.jpn.com/column/4c-analysic/)

| 4P分析<br>（企業の売り手視点） | 4C分析<br>（顧客の買い手視点） | 内容と対比関係 |
| --- | --- | --- |
| **Product（製品）** | **Customer Value（顧客価値）** | 企業が作る製品機能 ↔ 顧客が得られるベネフィットや課題解決 |
| **Price（価格）** | **Cost（顧客の負担費用）** | 企業が設定した販売価格 ↔ 顧客が支払う金銭的・時間的コスト |
| **Place（流通・場所）** | **Convenience（利便性）** | 企業の販売経路や店舗 ↔ 顧客にとっての購入・入手のしやすさ（Web等の利便性） |
| **Promotion（販促）** | **Communication（対話・関係性）** | 企業からの一方的な広告・宣伝 ↔ 顧客との双方向の対話や情報共有 |

## **4-2. 消費者購買行動モデルの変遷（AIDMAからAISAS・SIPSへ）**

メディアの進化に伴い、生活者が商品を知ってから購入・行動に至るまでのプロセス（心理モデル）は変化しています。

![出典：[https://www.sendenkaigi.com/marketing/media/hansokukaigi/007304/](https://www.sendenkaigi.com/marketing/media/hansokukaigi/007304/)](https://images.microcms-assets.io/assets/9c883224793c4361bfa991c4e6710e04/83d72e599f464c26be993691d85716e2/074_01.jpg)

出典：[https://www.sendenkaigi.com/marketing/media/hansokukaigi/007304/](https://www.sendenkaigi.com/marketing/media/hansokukaigi/007304/)

### **【AIDMA（アイドマ：マス広告時代）】**

テレビCMや新聞・雑誌広告など、企業から消費者への一方通行のメディアが中心だった時代のモデル。

| 段階（AIDMA） | プロセス・意味 | 具体的な行動・状態 |
| --- | --- | --- |
| **Attention** | 認知・注目 | 広告を見て商品を知る。 |
| **Interest** | 興味・関心 | 面白そうだと興味を持つ。 |
| **Desire** | 欲求 | 欲しいと感じる。 |
| **Memory** | 記憶 | 商品名や特徴を覚える。 |
| **Action** | 行動 | 店舗に行って購入する。 |

### **【AISAS（アイサス：ネット検索時代）】**

広告代理店の電通が提唱。インターネットとWeb検索が普及した現代の購買行動モデル。

| 段階（AISAS） | プロセス・意味 | 具体的な行動・状態 |
| --- | --- | --- |
| **Attention** | 認知・注目 | Web広告やニュース、SNSで商品を知る。 |
| **Interest** | 興味・関心 | 興味を持つ。 |
| **Search** | 検索 | **自ら能動的にGoogleやSNS、比較サイトで口コミや情報を検索する。** |
| **Action** | 行動 | WebサイトやECサイト上で購入・申込みを行う。 |
| **Share** | 共有 | **商品を使った感想や評価を、SNSやレビューサイトで他者と共有・発信する。** |

<aside>
💡

**AISASの構造的特徴**

消費者が能動的に情報を調べる**「Search（検索）」と、体験後に他者へ拡散する「Share（共有）」**という2つの行動が組み込まれており、共有された情報が別のユーザーの認知や検索につながる「循環構造」を持ちます。

</aside>

### **【SIPS（シップス：SNS・ソーシャルメディア時代）】**

ソーシャルメディアが定着した時代の共感と参加を軸とする購買行動モデル。

| 段階（SIPS） | プロセス・意味 | 具体的な行動・状態 |
| --- | --- | --- |
| **Sympathize** | 共感する | 投稿やメッセージに共感する。 |
| **Identify** | 確認する | 有益か、信頼できるかを確認する。 |
| **Participate** | 参加する | いいね、リポスト、購入などの行動で参加する。 |
| **Share & Spread** | 共有・拡散 | 友人に共有・拡散し、さらなる共感を広げる。 |

## **4-3. Webサイトの成果指標とコンバージョン最適化**

Webマーケティングでは、サイトの成果を数値で把握し、目標達成に向けて継続的に改善を行います。

### **【KGI と KPI（目標設計の基本指標）】**

Webマーケティングでは、サイトの制作・運用にあたって「最終ゴール」と「中間プロセス」の指標を明確に設定します。

| 指標 | 正式名称 | 意味と定義 |
| --- | --- | --- |
| **KGI** | **Key Goal Indicator**<br>（重要目標達成指標） | ビジネスやサイトが達成すべき**「最終的な目標（ゴール）」** |
| **KPI** | **Key Performance Indicator**<br>（重要業績評価指標） | KGIを達成するための**「中間目標（プロセス指標）」** |

### **【コンバージョン（CV: Conversion）とは】**

サイト訪問者が運営者の設定した「最終目標アクション」を達成すること（購入、問い合わせ、資料請求、会員登録等）。

### **【マーケティングファネル（漏斗）の考え方】**

認知から購入に至るまで、段階が進むにつれてユーザーが絞り込まれ、逆三角形の漏斗（ファネル）のようになる購買行動モデル。
