# **1. 情報デザイン（インフォメーションデザイン）と情報アーキテクチャ**

## **1-1. インフォメーションデザインと情報構造化の基礎**

複雑な情報をユーザーが直感的に理解できるように整理・構造化するための基礎概念と代表的な情報構造モデルです。

### **【インフォメーションデザイン（Information Design）】**
受け手が情報をスムーズに理解し、迷わず的確な行動をとれるように、**情報を分かりやすく整理・視覚化・伝達する設計手法**。単なる見た目の装飾ではなく、「情報の伝わりやすさ」そのものを論理的に最適化します。

### **【情報アーキテクチャ（IA: Information Architecture）】**
Webサイト内の膨大なコンテンツを分類・整理し、**目的の情報へ迷わず辿り着けるようにWebサイト全体の情報構造・導線を論理的に設計する技術や思想**。建築の設計図のようにサイトの骨格を定義します。

### **【代表的な4つの情報構造モデル】**

- **階層型（ツリー構造 / ヒエラルキー型）：**
  - トップページを頂点として、カテゴリごとに下位階層へ枝分かれする最も一般的で基本的な構造。
  - 構造が明確で全体像を把握しやすい反面、階層が深すぎるとクリック回数が増加します。
  - 適用例：コーポレートサイト、行政サイト、一般的なWebサイト全般。
- **線形構造（リニア構造 / シーケンシャル型）：**
  - ページを1本道（直線的）に順序立てて進ませる構造。
  - 次のステップが明確で迷わない反面、自由な移動には適しません。
  - 適用例：ECサイトの購入完了フロー、会員登録フォーム、Webアンケート、Tutorial。
- **ネットワーク型（Web型）：**
  - 厳密な上下関係を持たず、関連する情報同士が網の目のようにハイパーリンクで相互に結ばれている自由な構造。
  - 自由に回遊できる反面、現在地を見失いやすい（迷子になりやすい）特徴があります。
  - 適用例：Wikipedia、ブログの関連記事リンク、ナレッジベース。
- **ファセット型（多面的絞り込み構造）：**
  - 単一の階層ツリーではなく、「価格」「色」「サイズ」「ブランド」など複数の属性（ファセット）で横断的に絞り込む構造。
  - ユーザーが求める条件の組み合わせで目的のアイテムを素早く特定できます。
  - 適用例：総合ECサイト、不動産物件検索、求人サイト。

```
［代表的な情報構造モデルのイメージ］
  ［階層型（ツリー構造）］        ［線形構造（リニア）］        ［ネットワーク型（Web型）］
          [TOP]               [Step 1] -> [Step 2] -> [Step 3]       (A) <---> (B)
        ／     ＼                                                    ^ \     / ^
     [Cat A]  [Cat B]                                                |  ( C )  |
     ／   ＼   ／   ＼                                               v /     \ v
   [p1]  [p2] [p3]  [p4]                                             (D) <---> (E)
```

- **階層の深さ（ディープ構造 vs ワイド構造）：**
  - **ディープ構造（階層が深すぎる）：** カテゴリの分類が細かすぎてクリック回数が増え、ユーザーが現在地を見失いやすくなります。
  - **ワイド構造（階層が浅すぎる）：** 1つの画面に並ぶ選択肢が多すぎて、どれを選べばよいか迷ってしまいます。
  - **3クリックルール：** ユーザーがトップページから3回以内のクリックで目的の情報に辿り着ける階層設計が理想とされます。

## **1-2. サイト設計の主要ドキュメント**

Webサイトの制作現場では、制作チームや関係者全体でサイトの全体像や各画面の構成を共有するために、段階に応じた設計ドキュメントを作成します。

```
［Webサイト制作の設計フロー］
  要件定義 ──> サイトマップ / ディレクトリマップ ──> ワイヤーフレーム ──> モックアップ ──> プロトタイプ
  (目的・IA)         (サイト全体の全体構成図)             (画面の骨組み設計)      (静止画カンプ)     (動的な試作品)
```

| 設計ドキュメント | 形式・主な作成ツール | 役割と特徴 |
| --- | --- | --- |
| **サイトマップ（Site Map）** | ツリー図、階層図 | **Webサイト全体のページ構成や階層関係を図式化・視覚化した全体構成図。** サイト全体のボリュームやカテゴリの包含関係を俯瞰・一覧するために用います。 |
| **ディレクトリマップ（Directory Map）** | 表計算ツール（Excel、Googleスプレッドシート等） | **サイト内の全ページのURL、タイトル、階層構造、ファイル名、概要などを一覧表にした管理リスト。** 制作進行管理やサーバー上のファイル構成の基準となります。 |
| **ワイヤーフレーム（Wireframe）** | 単色の線画・枠線（Figma、XD、手書き等） | **各ページのレイアウト、コンテンツの配置、情報の優先順位を示した画面の設計図（骨組み）。** 色や装飾を決める前段階で作成します。サイト全体の一覧ではなく各画面の構成を定義します。 |
| **モックアップ（Mockup）** | 静止画像デザインカンプ（Figma、Photoshop等） | ワイヤーフレームに配色・タイポグラフィ・写真などのビジュアルデザインを適用した**「完成予想の静止画」**。 |
| **プロトタイプ（Prototype）** | インタラクティブな試作品（Figmaプロトタイプ等） | 実際にボタンクリックや画面遷移、アニメーションなどの**動作・操作感（インタラクション）を検証できる動的な試作品**。 |

## **1-3. Webサイトの目的別分類と設計の要点**

Webサイトは、発注者が達成したいビジネスゴールによってターゲットや求められる構造が大きく異なります。

### **【目的別の代表的なWebサイト】**
- **コーポレートサイト（企業サイト）：**
  企業の事業内容、企業理念、会社概要、IR情報、採用情報などを発信し、取引先や社会からの**「信頼性・認知度を向上させる」**ためのサイト。
- **サービスサイト / ブランドサイト：**
  特定の製品やサービス、ブランドの世界観を伝え、**「認知拡大・ブランディング・資料請求・商談獲得」**を目的とするサイト。
- **ECサイト（Electronic Commerce: 電子商取引サイト）：**
  Web上で商品やサービスを直接販売・決済するサイト。商品の見つけやすさ（ファセット検索）と、カゴ落ち（購入前の離脱）を防ぐスムーズな決済フロー（リニア構造）が重要。
- **ランディングページ（LP: Landing Page）：**
  Web広告や検索結果からの流入ユーザーを受け止め、**「問い合わせ」「購入」「会員登録」など特定の1つのアクション（コンバージョン）に直結させるために特化した縦長1ページのサイト**。他ページへのリンクを極力排除し、ストーリー仕立てで訴求します。
- **オウンドメディア（Owned Media）：**
  企業が自社で保有・運営するメディア（ブログ記事や専門コラム等）。ユーザーにとって有益な情報を提供し続けることで検索流入を増やし、見込み顧客との関係性を構築します。

# **2. UI（ユーザーインターフェース）設計とナビゲーション体系**

## **2-1. Webナビゲーションの6大分類**

ユーザーがWebサイト内で迷子にならず、目的のページへスムーズに辿り着けるように誘導するための道しるべです。

| ナビゲーション種別 | 配置場所 | 役割と特徴 |
| --- | --- | --- |
| **① グローバルナビゲーション（GNav）** | ページ上部（ヘッダー直下など全ページ共通） | サイト内の全ページに共通して設置される最重要メニュー。サイトの主要なカテゴリへの移動手段を提供します。 |
| **② ローカルナビゲーション（LNav）** | 画面の左側・右側のサイドバーなど | 現在閲覧しているカテゴリ内、または同一階層内の詳細ページ群へ移動するためのメニュー。 |
| **③ パンくずリスト（Breadcrumb）** | メインコンテンツの上部 | **トップページから現在地までの経路を、ツリー構造を持ったハイパーリンクの一覧として示すもの。** |
| **④ フッターナビゲーション** | ページ最下部（フッター領域） | サイトマップ、利用規約、プライバシーポリシー、著作権表示、お問い合わせなど、補助的だが重要なリンクを網羅します。 |
| **⑤ ユーティリティナビゲーション** | ヘッダーの右上など目立たない補助位置 | コンテンツ閲覧とは直接関係ないが、サイト利用を支援する便利機能リンク（ログイン、会員登録、サイト内検索、言語切替等）。 |
| **⑥ コンテキストナビゲーション** | 本文内、記事の下部など | 文脈（コンテキスト）に応じたリンク。「関連記事」「この商品を買った人はこちらもチェック」など。 |

### **【パンくずリスト（Breadcrumb Navigation）】**
童話『ヘンゼルとグレーテル』で道にパンくずを落として目印にしたエピソードに由来するナビゲーションです。
- **表記例：** `HOME > サービス紹介 > Webサイト制作 > LP制作プラン`
- **ユーザー体験の向上：** ユーザーが「今サイト内のどこにいるか（現在地）」を一目で把握でき、上位階層へ1クリックで戻れます。
- **SEO効果：** 検索エンジンのクローラーがサイトの階層構造を正確に理解できるようになります。
- **セマンティックマークアップ：** HTMLでは `<nav aria-label="パンくずリスト">` と `<ol>`（順序付きリスト）を用いて実装します。

## **2-2. 代表的なUIコンポーネントと操作設計**

ユーザーが直感的に操作できるよう、Webページでは機能や用途に応じたUIコンポーネントを適切に使い分けます。

- **CTAボタン（Call to Action: 行動喚起）：**
  ユーザーに「購入」「会員登録」「資料請求」などの目標アクションを促すための最重要ボタン。周囲と明確にコントラストをつけた目立つ配色と分かりやすいラベルを用います。
- **マイクロコピー（Microcopy）：**
  ボタンのラベル、入力フォームのプレースホルダー、エラーメッセージ、確認画面の補足文など、UIの細部に配置される極めて短い言葉。「登録は無料・1分で完了」のようにユーザーの不安や疑問を解消して行動を後押しします。
- **プログレスバー（Progress Bar）：**
  ファイルの転送やダウンロード、フォーム入力の進捗状況を視覚的にパーセンテージやバー形式で表示するUI。ユーザーの待ち時間の不安を軽減します。
- **モーダルウィンドウ（Modal Window）：**
  画面の前面にポップアップ表示され、ユーザーが閉じるか何らかのアクションを完了するまで親画面の操作を制限するダイアログ。重要なお知らせや確認画面に用います。
- **カルーセル（Carousel / スライダー）：**
  複数のバナーや画像を横方向にスライドさせて切り替え表示するUIコンポーネント。限られたスペースで複数のコンテンツを提示できます。

## **2-3. UI設計における心理学・認知工学の基本原則**

ユーザーが無意識のうちに正しく操作できるよう、人間の認知特性や心理学に基づいたUI設計の原則を活用します。

- **アフォーダンスとシグニファイア：**
  - **アフォーダンス（Affordance）：** 物体が本来持っている「行為を可能にする物理的性質」（例：画面はタップできる性質を持つ）。
  - **シグニファイア（Signifier）：** ドナルド・ノーマンが提唱した、**「どこをどう操作すればよいかをユーザーに手掛かりとして示す視覚的合図」**（例：立体的な影をつけたボタン、青い下線付きリンクテキスト）。
- **メタファー（隠喩）：**
  現実世界の道具や概念を画面上のアイコンや操作に置き換えて表現すること（例：ゴミ箱アイコン＝削除、虫眼鏡アイコン＝検索、買い物かごアイコン＝カート）。
- **メンタルモデル（Mental Model）：**
  ユーザーが「これはこう動くに違いない」と頭の中で持っている思い込みや予測。「下線付きの青い文字はリンク」「右上の×ボタンは閉じる」など、既存のメンタルモデルに沿った設計が直感的な操作感を生みます。
- **ファーストビュー（Above the Fold）：**
  Webページを開いたときにスクロールせずに最初に見える画面領域。ユーザーはわずか数秒でそのサイトを読み進めるか離脱するかを判断するため、重要情報やCTAを配置します。
- **視線誘導のパターン（Fの法則とZの法則）：**
  - **Fの法則：** テキスト主体のWebページ（記事や検索結果など）を閲覧する際、ユーザーの視線がアルファベットの「F」の形を描くように動く現象（上部を横に読み、少し下がって短く横に読み、左端を縦に流し見する）。
  - **Zの法則：** 画像やバナーが配置されたレイアウト（LPやチラシ、トップページなど）を閲覧する際、視線がアルファベットの「Z」の形を描くように左上→右上→左下→右下へと動く現象。

# **3. UX（ユーザーエクスペリエンス）とユーザビリティ**

## **3-1. UIとUXの違い・包括関係**

UIはユーザーと製品をつなぐ「接点」であり、UXはその利用を通じて得られる「体験の総体」を指します。

| 概念 | 正式名称 | 意味と役割 | 具体例での違い |
| --- | --- | --- | --- |
| **UI** | User Interface<br>（ユーザーインターフェース） | ユーザーと製品が接する**「接点・道具・見た目」**。<br>ボタン、画面レイアウト、文字、配色、操作部など。 | レストランの「お皿、フォーク、内装、メニュー表のデザイン」 |
| **UX** | User Experience<br>（ユーザーエクスペリエンス） | 製品やサービスの利用を通じてユーザーが得る**「体験・印象・感情・満足感の総体」**。 | レストランでの「料理の味、接客の心地よさ、食事を楽しんだ全体の幸福感」 |

- **UIとUXの関係性：**
  優れたUIは、優れたUXを生み出すための重要な構成要素です。ただし、**「UIが美しい ＝ 優れたUX」とは限りません**。どれだけデザインが美麗でも、表示速度が極端に遅かったり、注文手続きでエラーばかり出るサイトは悪いUXとなります。

---

## **3-2. ユーザビリティの定義と基本特性（ISO 9241-11 ＆ ニールセン）**

使いやすさ（ユーザビリティ）は国際規格や人間工学によって明確に定義されており、定量的・定性的な評価基準を持ちます。

### **【国際規格 ISO 9241-11 によるユーザビリティの定義】**
**「特定の利用状況において、特定のユーザーによって、ある製品が、指定された目標を達成するために用いられる際の、有効さ、効率、及び満足度の度合い。」**

- **ユーザビリティを構成する3大要素：**
  1. **有効さ（Effectiveness）：** ユーザーが目標を正確に、完全に達成できている度合い（目的が達成できたか）。
  2. **効率（Efficiency）：** 目標を達成するために費やした資源・労力・時間と、得られた結果との関係（手早く簡単にできたか）。
  3. **満足度（Satisfaction）：** 製品を使用したことによる快適さや好意的な態度の度合い（気持ちよく使えたか）。
- **利用状況（Context of Use）：**
  ユーザビリティは絶対的なものではなく、「誰が（ユーザー）」「何のために（目標）」「どのような環境で（物理・社会的環境）」使うかによって評価が変化します。

### **【ヤコブ・ニールセンの「ユーザビリティの5大特性」】**
Webユーザビリティの第一人者であるヤコブ・ニールセン（Jakob Nielsen）博士が提唱した使いやすさの5つの品質属性です。
1. **学習しやすさ（Learnability）：** 初めて使うユーザーでも、すぐに基本操作を習得できること。
2. **効率性（Efficiency）：** 一度操作を覚えたら、手際よく作業を進められること。
3. **記憶しやすさ（Memorability）：** しばらく使っていなかったユーザーでも、迷わず操作を思い出せること。
4. **エラー発生率の低さ（Errors）：** ユーザーがエラーを起こしにくく、起こしても迅速に回復できること。
5. **主観的満足度（Satisfaction）：** 使っていて心地よく、満足できること。

---

## **3-3. 代表的なユーザビリティ評価手法**

Webサイトやシステムの使いやすさを検証・改善するために、対象者や目的に応じた評価手法を実施します。

| 評価手法 | 概要と特徴 | メリットと活用場面 |
| --- | --- | --- |
| **ユーザビリティテスト<br>（行動観察法）** | **実際のターゲットユーザー（被験者）にタスクを与えて操作してもらい、その行動や様子を観察・分析する手法。** | 開発者の思い込みを排し、実際のユーザーが画面のどこで迷い、つまずいたかを直接発見できます。 |
| **思考発話法<br>（シンクアラウド）** | **ユーザビリティテストの実施中、被験者に「考えていることや疑問」をリアルタイムで声に出しながら操作してもらう手法。** | 操作行動の背景にある**内面的な思考プロセスや心理**を正確に把握できます。 |
| **ヒューリスティック評価** | **専門家（エキスパート）が、確立された経験則（ヒューリスティクス）やガイドラインに照らして問題点を抽出・評価する手法。** | 被験者を集めるコストや時間をかけずに、開発初期から短期間・低コストで迅速に課題を洗い出せます。 |

---

## **3-4. 人間中心設計（HCD）とUXデザインの設計ツール**

ユーザーの視点に立って質の高い体験（UX）を設計するための思想と、その実現に向けた主要な設計ツールです。

- **人間中心設計（HCD: Human-Centered Design / ISO 9241-210）：**
  システムやWebサイトを開発する際、開発者や企業の都合・技術先行ではなく、**「実際にそれを使う人間（ユーザー）のニーズや使いやすさ」に主眼を置いて設計を進める思想・プロセス**。調査、プロトタイプ、評価を何度も反復（イテレーション）することで質の高いUXを実現します。
- **ペルソナ（Persona）：**
  ターゲット顧客層の中から設定する、**実在するかのような「架空の典型的なユーザー像」**（氏名、年齢、職業、ライフスタイル、ITリテラシー、悩み、目標など）。開発チーム間での認識のブレを防ぎます。
- **カスタマージャーニーマップ（CJM: Customer Journey Map）：**
  ペルソナが商品やサービスを認知し、情報収集、比較検討、購入を経てファン化に至るまでの**一連のプロセスを時系列で可視化した図**。ユーザーの不安・不満（ペインポイント）を特定し改善策を立案します。

# **4. Webマーケティング戦略と基本フレームワーク**

## **4-1. マーケティング分析の4大フレームワーク**

Webサイトの戦略立案や改善施策の策定において、環境や顧客ターゲットを論理的に分析するための代表的なフレームワークです。

### **① 3C分析（ミクロ環境分析）**
自社を取り巻く市場環境を3つの視点から客観的に把握するフレームワーク。
- **Customer（市場・顧客）：** 顧客ニーズ、市場規模、購買行動の動向。
- **Competitor（競合）：** 競合企業の強み、弱み、シェア、戦略。
- **Company（自社）：** 自社の強み（USP: 独自の強み）、弱み、保有リソース。

### **② SWOT分析（内部・外部環境分析）**
自社の内部環境と外部環境を4つの要素に整理・クロス分析するフレームワーク。
- **内部環境（コントロール可能）：**
  - **S（Strengths: 強み）：** 競合に勝る自社の特長や技術力。
  - **W（Weaknesses: 弱み）：** 自社の課題や不足しているリソース。
- **外部環境（コントロール不可能）：**
  - **O（Opportunities: 機会）：** 法改正、市場拡大、トレンドなどの追い風。
  - **T（Threats: 脅威）：** 新規参入、景気後退、技術の陳腐化などの逆風。

### **③ STP分析（ターゲットと立ち位置の決定）**
自社の商品やWebサイトが「誰に」「どのような価値を」提供するかを定めるフレームワーク。
- **S（Segmentation: 市場細分化）：** 年齢、性別、地域、行動特性などで市場を切り分ける。
- **T（Targeting: 標的市場の選定）：** 細分化した市場の中から、自社が狙うターゲットを絞り込む。
- **P（Positioning: 立ち位置の確立）：** 競合他社と比較し、自社独自のポジション（差別化ポイント）を築く。

### **④ 4P分析（売り手視点） vs 4C分析（買い手視点）**
マーケティングミックスを設計する際、企業の視点（4P）と顧客の視点（4C）を対比させて検討するフレームワーク。

| 4P分析（企業の売り手視点 / マッカーシー提唱） | 4C分析（顧客の買い手視点 / ローターボーン提唱） | 内容と対比関係 |
| --- | --- | --- |
| **Product（製品）** | **Customer Value（顧客価値）** | 企業が作る製品機能 ↔ 顧客が得られるベネフィットや課題解決 |
| **Price（価格）** | **Cost（顧客の負担費用）** | 企業が設定した販売価格 ↔ 顧客が支払う金銭的・時間的コスト |
| **Place（流通・場所）** | **Convenience（利便性）** | 企業の販売経路や店舗 ↔ 顧客にとっての購入・入手のしやすさ（Web等の利便性） |
| **Promotion（販促）** | **Communication（対話・関係性）** | 企業からの一方的な広告・宣伝 ↔ 顧客との双方向の対話や情報共有 |

## **4-2. 消費者購買行動モデルの変遷（AIDMAからAISAS・SIPSへ）**

メディアの進化に伴い、生活者が商品を知ってから購入・行動に至るまでのプロセス（心理モデル）は変化しています。

```
［購買行動モデルの変遷］
［マス広告時代］      AIDMA: Attention -> Interest -> Desire -> Memory -> Action
［ネット検索時代］    AISAS: Attention -> Interest -> 【Search】 -> Action -> 【Share】
［SNS共感時代］      SIPS : Sympathize -> Identify -> Participate -> Share & Spread
```

### **① AIDMA（アイドマ：マス広告時代）**
テレビCMや新聞・雑誌広告など、企業から消費者への一方通行のメディアが中心だった時代のモデル。
- **A（Attention: 認知）：** 広告を見て商品を知る。
- **I（Interest: 関心）：** 面白そうだと興味を持つ。
- **D（Desire: 欲求）：** 欲しいと感じる。
- **M（Memory: 記憶）：** 商品名や特徴を覚える。
- **A（Action: 行動）：** 店舗に行って購入する。

### **② AISAS（アイサス：ネット検索時代）**
広告代理店の電通が提唱。インターネットとWeb検索が普及した現代の購買行動モデル。
- **A（Attention: 認知）：** Web広告やニュース、SNSで商品を知る。
- **I（Interest: 関心）：** 興味を持つ。
- **S（Search: 検索）：** **自ら能動的にGoogleやSNS、比較サイトで口コミや情報を検索する。**
- **A（Action: 行動）：** WebサイトやECサイト上で購入・申込みを行う。
- **S（Share: 共有）：** **商品を使った感想や評価を、SNSやレビューサイトで他者と共有・発信する。**
- **最大の特徴：** 消費者が能動的に情報を調べる**「Search（検索）」**と、体験後に他者へ拡散する**「Share（共有）」**という2つの行動が組み込まれており、共有された情報が別のユーザーの認知や検索につながる循環構造を持ちます。

### **③ SIPS（シップス：SNS・ソーシャルメディア時代）**
ソーシャルメディアが定着した時代の共感と参加を軸とする購買行動モデル。
- **S（Sympathize: 共感する）：** 投稿やメッセージに共感する。
- **I（Identify: 確認する）：** 有益か、信頼できるかを確認する。
- **P（Participate: 参加する）：** いいね、リポスト、購入などの行動で参加する。
- **S（Share & Spread: 共有・拡散）：** 友人に共有・拡散し、さらなる共感を広げる。

## **4-3. Webサイトの成果指標とコンバージョン最適化**

Webマーケティングでは、サイトの成果を数値で把握し、目標達成に向けて継続的に改善を行います。

### **【コンバージョン（CV: Conversion）とは】**
Webサイトを訪れたユーザーが、サイト運営者が設定した「最終的な目標アクション」を達成すること（ECサイトの購入完了、問い合わせ送信、資料請求、会員登録等）。

### **【マーケティングファネル（漏斗）の考え方】**
認知から購入に至るまで、ユーザーの人数は段階が進むごとに絞り込まれ、逆三角形の漏斗（ファネル）のような形状になります。

```
［マーケティングファネルの構造］
   認知段階   【 広範なユーザーがサイトを認知・訪問 】
      ↓          （離脱）
   興味・関心 【 詳細ページやサービス内容を閲覧 】
      ↓          （離脱）
   比較・検討 【 カートへの追加、見積もり入力 】
      ↓          （カゴ落ち・入力途中離脱）
   行動（CV） 【 購入完了・申込み完了（コンバージョン） 】
```

### **【EFO（Entry Form Optimization: 入力フォーム最適化）】**
コンバージョン直前の最後の関門である「入力フォーム」で、ユーザーが入力の面倒さや不安を感じて離脱（カゴ落ち）してしまうのを防ぐUI/UX改善施策です。
- **入力項目を必要最小限に絞る：** 不要なアンケートや任意項目を削り、入力負担を減らします。
- **郵便番号からの住所自動入力：** 郵便番号を入力すると市区町村まで自動補完します。
- **リアルタイムのエラー表示：** 送信ボタンを押した後ではなく、入力した瞬間にエラー内容や修正方法を案内します。
- **ステップバーの表示：** 「入力 ➔ 確認 ➔ 完了」のように全体の残りステップ数を明示し、心理的負担を軽減します。
