# **1. インターネット通信プロトコル（TCP/IP）**

## **1-1. TCP/IP 4階層モデルとトランスポート層**

インターネットの通信は、「TCP/IP 4階層モデル」に基づき、階層ごとに役割分担して行われます。

### **【TCP/IP 4階層モデルとカプセル化】**

```
［TCP/IP 4階層モデルとカプセル化］
    送信側（クライアント）                           受信側（サーバ）
   ┌───────────────────────┐                     ┌───────────────────────┐
   │ ① アプリケーション層  │ ── データ ────────> │ ① アプリケーション層  │ (HTTP, DNS等)
   ├───────────────────────┤                     ├───────────────────────┤
   │ ② トランスポート層    │ ── ヘッダ追加 ────> │ ② トランスポート層    │ (TCP, UDP / 信頼性制御)
   ├───────────────────────┤                     ├───────────────────────┤
   │ ③ インターネット層    │ ── IPヘッダ追加 ──> │ ③ インターネット層    │ (IP / 経路制御)
   ├───────────────────────┤                     ├───────────────────────┤
   │ ④ ネットワークIF層    │ ── 電気・光信号 ──> │ ④ ネットワークIF層    │ (イーサネット, Wi-Fi)
   └───────────────────────┘                     └───────────────────────┘
```

| 階層 | 主な役割・機能 | 代表的プロトコル |
| --- | --- | --- |
| **第4層：アプリケーション層** | 各アプリ固有のサービス（Web閲覧、メール送受信等）を提供。 | **HTTP, HTTPS, DNS, FTP, SFTP, SMTP, POP3** |
| **第3層：トランスポート層** | ポート番号を基に相手アプリへ確実に届ける（エラー・順序制御）。 | **TCP**（高信頼・確認応答あり）、**UDP**（高速・リアルタイム） |
| **第2層：インターネット層** | IPアドレスを基にパケットを宛先まで運ぶ（経路選択/ルーティング）。 | **IP**（IPv4, IPv6）、**ICMP** |
| **第1層：ネットワークIF層** | 同一回線内の機器間で電気信号や電波を用いて伝送。 | **Ethernet（有線LAN）**、**Wi-Fi（無線LAN）** |

### **【TCP と UDP の違い（トランスポート層）】**

| 比較項目 | TCP（Transmission Control Protocol） | UDP（User Datagram Protocol） |
| --- | --- | --- |
| **通信方式** | **コネクション型**（事前接続：**3ウェイハンドシェイク**） | **コネクションレス型**（事前接続なしの一方送信） |
| **信頼性** | **極めて高い**（到達確認・順序制御・再送制御あり） | **低い**（喪失時の再送なし） |
| **転送速度** | やや低速（確認手順があるため） | **非常に高速**（オーバーヘッド極小） |
| **主な用途** | **Web閲覧（HTTP/HTTPS）、メール、ファイル転送** | **DNS問い合わせ、音声通話（VoIP）、動画配信** |

## **1-2. 主要プロトコルとデータ保存技術**

アプリケーション層の通信プロトコルとデータ保存技術は、Webコンテンツの安全な送受信や状態管理を実現します。

### **【主要な通信プロトコル一覧】**

| プロトコル名 | 概要・役割 | ポート | セキュリティ・実務知識 |
| --- | --- | --- | --- |
| **HTTP** | Webブラウザとサーバ間でページをやり取りする。 | **80** | **通信が平文**で盗聴・改ざんの危険あり。 |
| **HTTPS** | HTTP通信を**SSL/TLSで暗号化**した安全なプロトコル。 | **443** | 暗号化＋サイトの真正性を証明（常時SSLが標準）。 |
| **DNS** | ドメイン名とIPアドレスを相互変換（名前解決）。 | **53** | インターネットの住所録。 |
| **FTP** | サーバとクライアント間でファイルを転送する。 | **21** | **ID・PW・データが平文**で送信され現在は非推奨。 |
| **FTPS** | **FTP通信をSSL/TLSで暗号化**したプロトコル。 | **990等** | 従来のFTP仕組みをSSL/TLS暗号化。 |
| **SFTP** | **SSH（暗号化シェル）の仕組みを利用**してファイル転送。 | **22** | **FTPSとは別体系**（SSH基盤）。現在のWeb制作標準。 |

<aside>
💡

**FTPS と SFTP の違い：**
どちらも安全な暗号化ファイル転送ですが、**暗号化の仕組みが根本的に異なります**（FTPSはSSL/TLS、SFTPはSSH基盤）。「一方が平文である」「両者は同一である」とする誤り選択肢に注意。

</aside>

### **【HTTPの進化とブラウザ保存技術】**

- **HTTPの進化：**
  - **HTTP/1.1：** 順次要求処理のため画像が多いと遅延。
  - **HTTP/2：** 1本のTCP接続で複数要求を同時に処理する**「多重化」**で高速化。
  - **HTTP/3：** **UDPベースのQUICプロトコル**を採用し接続開始遅延を最小化。
- **ブラウザデータ保存技術：**
  - **Cookie（約4KB）：** リクエストごとに**自動送信**。ログインセッション維持（`Secure`, `HttpOnly`, `SameSite` 属性で保護）。
  - **LocalStorage（約5MB）：** 自動送信なし。**永続保存**（ダークモード設定等）。
  - **SessionStorage（約5MB）：** 自動送信なし。**タブを閉じるまで有効**（入力下書き等）。

## **1-3. HTTPステータスコードの体系**

HTTPステータスコードは、クライアントからのリクエストに対するサーバーの処理結果を3桁の数値で通知する仕組みです。

### **【代表的なHTTPステータスコード】**

| コード | 分類・英語名称 | 意味と詳細 |
| --- | --- | --- |
| **`200`** | **成功 / OK** | **リクエスト成功（正常応答）** |
| **`301`** | **転送 / Moved Permanently** | **恒久的なURL移動**（SEO評価を引き継ぐサイト移転） |
| **`302`** | **転送 / Found** | **一時的なURL移動**（メンテナンス中の一時誘導） |
| **`401`** | **クライアントエラー / Unauthorized** | **認証が必要**（Basic認証やログイン未実施） |
| **`403`** | **クライアントエラー / Forbidden** | **アクセス禁止**（閲覧権限・パーミッション不備） |
| **`404`** | **クライアントエラー / Not Found** | **ページ未検出**（URL誤り・リンク切れ） |
| **`500`** | **サーバエラー / Internal Server Error** | **サーバ内部エラー**（プログラム文法エラーやシステム障害） |
| **`503`** | **サーバエラー / Service Unavailable** | **サービス利用不可**（アクセス集中による過負荷やメンテ中） |

# **2. IPアドレス・ドメインと標準化団体**

## **2-1. IPv4 と IPv6 の構造比較**

IPアドレスは、インターネット上の機器を識別するネットワーク番号であり、従来のIPv4と次世代のIPv6が存在します。

### **【IPv4とIPv6の構造表記】**

> **［IPv4アドレス（32ビット / ドット区切り10進数）］**  
> `192.0.2.1`（8bit × 4ブロック）  
> **［IPv6アドレス（128ビット / コロン区切り16進数）］**  
> `2001:0db8:0000:0000:0000:0000:0000:0001` ➔ 省略表記：`2001:db8::1`

### **【IPv4 と IPv6 の仕様比較】**

| 比較項目 | IPv4 | IPv6 |
| --- | --- | --- |
| **アドレス長** | **32ビット（4バイト）** | **128ビット（16バイト）** |
| **表記方法** | 8ビットずつ4つに分け、**10進数**をドット（`.`）で区切る。 | 16ビットずつ8つに分け、**16進数**をコロン（`:`）で区切る。 |
| **アドレス総数** | 2³² ＝ **約43億個**（枯渇問題） | 2¹²⁸ ＝ **約340澗個**（実質無制限） |
| **セキュリティ** | 後付けでIPsecを導入 | **IPsec（通信暗号化機能）を標準搭載** |

---

## **2-2. アドレス種別とDNS・通信セキュリティ**

ネットワーク通信のセキュリティ技術は、安全な名前解決や不正ななりすましメールの防止を担保します。

### **【IPアドレス種別とDNSセキュリティ技術】**

- **グローバルIP vs プライベートIP：**
  インターネットで唯一の「グローバルIP」に対し、社内・家庭内のみで使う「プライベートIP」。境界ルータで**NAT/NAPT**により変換。
- **DNSレコード：** A（IPv4）、AAAA（IPv6）、CNAME（別名）、MX（メール配送先）、TXT（所有権証明・SPF）。
- **DNSSEC：** DNS応答に電子署名を付与し、偽サイトへ誘導する「DNSキャッシュポイズニング」を防ぐ。
- **送信ドメイン認証：** **SPF**（送信元IP検証）、**DKIM**（電子署名検証）、**DMARC**（認証失敗時の隔離・破棄指示）。
- **同一オリジンポリシー（SOP）とCORS：**
  ブラウザの安全のため、異なるオリジン間の通信を制限。外部API等を安全に呼び出すにはサーバ側で**CORS（Cross-Origin Resource Sharing）**許可ヘッダを出力。

### **【主要な標準化団体一覧】**

| 団体略称 | 正式名称 | 主な規格・役割 |
| --- | --- | --- |

# **3. 暗号化技術とセキュリティ基盤**

## **3-1. 共通鍵暗号方式 vs 公開鍵暗号方式**

暗号化通信は、暗号化と復号に使う「鍵」の扱い方によって共通鍵暗号方式と公開鍵暗号方式に分類されます。

### **【暗号化と復号の仕組み】**

> **［暗号化と復号の流れ］**  
> - **共通鍵暗号（同一鍵）：** 平文 ──［共通鍵で暗号化］──> 暗号文 ──［同じ共通鍵で復号］──> 平文  
> - **公開鍵暗号（ペア鍵）：** 平文 ──［受信者の公開鍵で暗号化］──> 暗号文 ──［受信者の秘密鍵で復号］──> 平文

### **【共通鍵暗号と公開鍵暗号の比較】**

| 比較項目 | 共通鍵暗号方式（対称暗号） | 公開鍵暗号方式（非対称暗号） |
| --- | --- | --- |
| **使用する鍵** | 暗号化と復号に**同一の1つの鍵**を使用。 | 暗号化用の**「公開鍵」**と復号用の**「秘密鍵」**のペア。 |
| **処理速度** | **極めて高速**（大量データ向き）。 | 暗号計算が複雑で**低速**（小データ向き）。 |
| **鍵の管理** | 相手ごとに鍵が必要で、受渡しが困難（**鍵配送問題**）。 | 公開鍵は誰にでも配布可能で管理が容易。 |
| **代表的暗号** | **AES**（現代標準）, DES | **RSA**, 楕円曲線暗号（ECC） |

> **ハイブリッド暗号方式（SSL/TLSの基本）：**
> 公開鍵暗号で通信用の「共通鍵」を安全に交換し、その後の大量通信は処理が速い「共通鍵暗号」で行う方式。

---

## **3-2. SSL/TLS暗号化通信と認証局（CA）**

SSL/TLS暗号化通信は、電子証明書を用いて通信経路の盗聴を防ぎ、接続先Webサイトの真正性を証明する技術です。

### **【SSL/TLSと電子証明書の仕組み】**

- **証明書の2大機能：** **通信の暗号化（盗聴防止）** ＋ **サイトの真正性の証明（なりすまし防止）**。
- **認証局（CA）：** 電子証明書を発行する第三者機関。失効確認はCRLやOCSP。
- **TLSへの移行：** 脆弱性のあるSSL 2.0/3.0は廃止され、現在は**TLS（1.2 / 1.3）**が標準。
- **HSTS：** 常にHTTPSで接続するようブラウザに強制指示し、ダウングレード攻撃を防止。
- **証明書期限切れのリスク：** 期限切れになるとブラウザに**「接続はプライベートではありません」等の強い警告画面**が表示され、アクセスが遮断される。

---

## **3-3. デジタル署名とハッシュ化**

デジタル署名とハッシュ化は、データの改ざん検知や送信者の本人証明を可能にする完全性保証技術です。

### **【完全性と本人証明の要素技術】**

- **情報セキュリティの3大要素（CIA）：**
  - **機密性（Confidentiality）：** 許可された者だけがアクセス可能（暗号化）。
  - **完全性（Integrity）：** データが改ざんされていない（デジタル署名、ハッシュ検証）。
  - **可用性（Availability）：** 必要なときにいつでも利用可能（冗長化、バックアップ）。
- **デジタル署名：** 送信者の**秘密鍵**で暗号化し、受信者が送信者の**公開鍵**で復号。**「本人証明（なりすまし防止）」**と**「改ざん検知」**を同時に実現。
- **パスワード保存：** 不可逆なハッシュ関数で変換して保存。逆引き対策として**ソルト（ランダム文字列付加）**と**ストレッチング（反復計算）**を行う。

# **4. サイバー攻撃と脅威の分類**

## **4-1. マルウェアの分類**

マルウェアは、コンピュータや利用者に不利益をもたらす悪意あるソフトウェアの総称です。

### **【代表的なマルウェアの種類と特徴】**

| マルウェア種別 | 動作特性・侵入方法 | 被害内容 |
| --- | --- | --- |
| **コンピュータウイルス** | 他の実行可能ファイルに**寄生して感染**し、宿主を通じて**自己増殖（自己複製）**。 | ファイル破壊、データ消去。 |
| **ワーム** | 他ファイルに寄生せず**単独で存在・動作**。ネットワークを介して**自己増殖・自己複製して拡散**。 | 回線帯域の枯渇、システム停止。 |
| **トロイの木馬** | 有益なソフトを**装って侵入**し裏で不正動作。**自己複製（自己増殖）は行わない**。 | バックドア開設、情報窃取。 |
| **ランサムウェア** | データを**勝手に暗号化して人質**にし、復号のために**身代金を要求**。 | 業務停止、データ損失。 |
| **スパイウェア / ボット** | キー入力を監視（キーロガー）したり外部から遠隔操作（C&Cサーバ）を受信。 | パスワード窃盗、DDoS踏み台。 |

---

## **4-2. Webアプリケーション脆弱性を狙う攻撃**

Webアプリケーションへの攻撃は、プログラムの入力検証の不備などの脆弱性を悪用して不正処理を発生させる攻撃です。

### **【主要なWebアプリケーション脆弱性と攻撃手法】**

- **クロスサイトスクリプティング（XSS）：** 入力欄に不正なJavaScriptを注入し、他ユーザーのブラウザ上で不正実行（Cookie窃取等）。
- **クロスサイトリクエストフォージェリ（CSRF）：** ログイン中のユーザーに罠リンクを踏ませ、意図しない偽リクエスト（送金や購入）をサーバに強制送信。
- **SQLインジェクション：** 入力欄に不正なSQL文を混入させ、データベースを不正操作・情報漏洩。
- **OSコマンドインジェクション：** シェルコマンド記号（`;` や `|`）を混入させ、サーバ上で不正OSコマンドを実行。
- **ディレクトリトラバーサル：** `../../` 記号により、Web非公開のシステムファイルを不正取得。
- **ゼロデイ攻撃：** 修正パッチが提供・適用される前に行われる攻撃。
- **セキュリティHTTPヘッダ：** クリックジャッキングを防ぐ `X-Frame-Options`、スクリプト実行元を制限する `Content-Security-Policy`（CSP）。
- **WAF（Web Application Firewall）：** 通信内容（ペイロード）を解析し、Webアプリ特有の攻撃（SQLi, XSS）を遮断する装置。

---

## **4-3. 人的・ネットワーク的攻撃手法**

人的・ネットワーク的攻撃は、利用者の心理的隙やネットワークプロトコルの特性を突いて被害を与える手口です。

### **【ネットワークおよび人的な攻撃手口】**

- **フィッシング（Phishing）：** 偽メールから本物そっくりの偽サイトへ誘導し、ID・カード番号を入力させる詐欺。
- **ソーシャルエンジニアリング：** 人間の不注意を突く手口（肩越しに覗くショルダーハッキング、ゴミ箱を漁るトラッシング）。
- **パスワード攻撃：** ブルートフォース（総当たり）、辞書攻撃、パスワードスプレー。
- **DoS / DDoS攻撃：** 大量アクセスでサーバを過負荷停止させる妨害攻撃（分散型がDDoS）。
- **ドライブバイダウンロード：** 改ざんサイトを閲覧しただけでマルウェアを自動感染させる攻撃。
- **標的型攻撃：** 特定組織を狙い、業務関連を装ったメール等で侵入する攻撃。
- **中間者攻撃（MitM）：** 通信者の間に割り込み、盗聴や改ざんを行う攻撃。

# **5. セキュリティ管理原則と防御体制**

## **5-1. 管理原則と多要素認証**

アクセス管理原則は、適切な権限設定と堅牢な本人確認によって不正アクセスを未然に防ぐ防御指針です。

### **【アクセス管理の原則と認証技術】**

- **最小権限の原則：** 担当者やプログラムに対し、任務に必要な**最小限のアクセス権限のみ**を付与。
- **多要素認証（MFA）：** 以下の異なる2要素以上を組み合わせた強固な本人確認。
  1. **知識情報：** パスワード、暗証番号、秘密の質問
  2. **所持情報：** スマホSMS、ワンタイムパスワードアプリ、ICカード
  3. **生体情報：** 指紋、顔、虹彩
- **認証（本人確認） vs 認可（権限付与）**
- **SSO（シングルサインオン）：** OAuth 2.0 / OpenID Connect による一括ログイン連携。
- **Wi-Fiセキュリティ：** 脆弱なWEPは廃止、**WPA2** や最新の **WPA3**（AES暗号化）を採用。

---

## **5-2. 組織的セキュリティ体制とリスク対応**

セキュリティ組織とリスク管理は、脅威の予兆検知からインシデント発生時の迅速な復旧までを組織横断で支える体制です。

### **【組織体制とリスクマネジメント】**

- **脆弱性管理：** **CVE**（脆弱性識別子）、**CVSS**（深刻度スコア0.0〜10.0）、ペネトレーションテスト（疑似侵入検証）。
- **対応組織：** **CSIRT**（社内事故対応チーム）、**SOC**（24時間監視チーム）、IPA / JPCERT/CC。
- **リスク対応の4分類：**
  1. **低減：** 対策で発生確率や被害を減らす（WAF導入、暗号化）。
  2. **回避：** 危険な業務やシステム自体を取りやめる。
  3. **移転：** 外部委託やサイバー保険で他者に移す。
  4. **保有：** 被害が軽微なため許容する。

# **6. Webフロントエンドスクリプト（JavaScript/DOM基礎）**

## **6-1. 基本仕様と配列**

JavaScriptは、ブラウザ上で動的な振る舞いやデータ処理を実装するためのスクリプト言語です。

### **【基本構文と配列の仕様】**

- **`<script>` タグ：** 外部JavaScriptファイル（`.js`）は**HTML内に複数読み込み可能**。
- **配列のインデックス：** 添字は必ず**「0」から始まる（0-indexed）**。

```javascript
// 配列の宣言とインデックス
var array = ["a", "b", "c"];
console.log(array[0]); // 出力: "a"
console.log(array[1]); // 出力: "b"
console.log(array[2]); // 出力: "c"
```

- **変数宣言：** `const`（再代入不可・定数）、`let`（再代入可能・ブロックスコープ）、`var`（旧規格）。
- **厳密等価演算子：** 型の一致まで判定する `===` を使用。

---

## **6-2. DOM操作とイベント処理**

DOM操作とイベント処理は、ユーザーの操作に応じてWebページの要素やスタイルを動的に書き換える仕組みです。

### **【DOM操作とイベントリスナーの実装】**

```html
<main>Webサイトのメインコンテンツ</main>
<button id="btn" onclick="hideElem()">メイン領域を非表示</button>

<script>
  const main = document.querySelector("main");

  // ボタンクリックで非表示
  function hideElem() {
    main.style.display = "none"; // CSSを直接操作
  }

  // addEventListener による監視
  const btn = document.getElementById("btn");
  btn.addEventListener("click", () => {
    main.classList.toggle("is-active"); // クラス切り替え
  });
</script>
```

- **要素取得：** `document.querySelector('セレクタ')`、`document.getElementById('id名')`。
- **イベント：** `click`、`change`、`submit`、`DOMContentLoaded`。
- **スタイル操作：** `要素.style.display = "none"`（非表示）/ `"block"`（表示）。
- **クラス操作：** `classList.add()`、`classList.remove()`、`classList.toggle()`。
- **フォーム値：** `document.querySelector('input').value` で取得。
- **Ajax / Fetch API：** 画面全体をリロードせず、非同期にサーバと通信して画面の一部を更新。
