# 第6回「Webシステム・通信プロトコルと情報セキュリティ」

# **1. Webシステムとサーバの基礎**

## **1-1. コンピュータの5大装置とCPUの役割**

コンピュータは、制御・演算・記憶・入力・出力という「5大装置」の連携によって動作します。

### **【コンピュータの5大装置の役割】**

```
                    ［コンピュータの5大装置とデータの流れ］
     ┌───────────┐      制御信号       ┌──────────────────────┐
     │           ├─────────────────>│       制御装置       │
     │ 入力装置  │                     ├──────────────────────┤ CPU (中央処理装置)
     │ (キーボード)│      データ入力      │       演算装置       │
     │ (マウス)   ├─────────────────>└──────────┬───────────┘
     └───────────┘                              │ データ受渡
                                                ▼
     ┌───────────┐      データ出力      ┌──────────────────────┐
     │ 出力装置  │<─────────────────┤    主記憶装置 (RAM)   │
     │ (画面・印)│                     └──────────┬───────────┘
     └───────────┘                                │ 読み書き
                                                  ▼
                                       ┌──────────────────────┐
                                       │ 補助記憶装置 (SSD/HDD)│
                                       └──────────────────────┘
```

| 装置分類 | 主な役割・機能 | 代表的機器・部品 |
| --- | --- | --- |
| **制御装置** | 命令を解読し、他装置へ指示・制御信号を送る。 | **CPU（中央処理装置）**内部 |
| **演算装置** | 四則演算や論理演算を実行する。 | **CPU（中央処理装置）**内部 |
| **記憶装置** | プログラムやデータを一時的・長期的に保管する。 | **主記憶（RAM）**、**補助記憶（SSD/HDD）** |
| **入力装置** | 外部からデータや指示を送り込む。 | **キーボード、マウス、タッチパネル** |
| **出力装置** | 処理結果を人間に認識できる形で提示する。 | **ディスプレイ、プリンタ、スピーカ** |

> **CPU（Central Processing Unit）：**
> 「制御装置」と「演算装置」を統合したコンピュータの頭脳。性能は**クロック周波数（GHz）**やコア数（マルチコア）で決まります。

### **【記憶装置（メモリとストレージ）の基礎】**

| 種別 | 主な役割・特徴 | 揮発性 | 代表例 |
| --- | --- | :---: | --- |
| **主記憶装置（RAM）** | 実行中のOSやプログラムを展開する作業領域。高速だが電源を切ると消える。 | **揮発性** | メインメモリ |
| **ROM** | 読み出し専用。PCの起動用プログラム（BIOS/UEFI）等を記録。 | **不揮発性** | 起動用ROM |
| **補助記憶装置（ストレージ）** | 電源を切ってもデータを長期保存する保管場所。 | **不揮発性** | **SSD**（高速・耐衝撃）、**HDD**（大容量・安価） |

- **揮発性：** 電源を切ると記憶しているデータが消える性質（作業机の上のような一時的な領域）。
- **不揮発性：** 電源を切ってもデータが消えずに保持される性質（引き出しや本棚のような長期保管先）。

## **1-2. サーバ・クライアント型とP2P**

Webシステムを含め、ネットワークでコンピュータ同士が通信する仕組みは、要求側と提供側を明確に分ける「サーバ・クライアント型」が基本となります。

### **【代表的なシステム形態】**

```
［サーバ・クライアント型（集中型）］      ［P2P型：Peer to Peer（分散型）］
   [クライアント]    [クライアント]           [端末(Peer)] ─── [端末(Peer)]
         │                 │                      │   ╲       ╱   │
         ▼                 ▼                      │     ╲   ╱     │
     ┌───────────────────────┐                    │     ╱   ╲     │
     │   サーバ (提供側)     │                    │   ╱       ╲   │
     └───────────────────────┘                [端末(Peer)] ─── [端末(Peer)]
   ※ Webブラウザ ⇄ Webサーバ の関係         ※ 各端末が対等に直接やり取り
```

- **サーバ・クライアント型：** リクエストする側（クライアント：Webブラウザ等）と処理・提供する側（サーバ：Webサーバ等）を分ける集中型モデル。
- **P2P（Peer to Peer）：** 全端末が対等にデータを送受信し合う分散型モデル。

> **関連用語：IoT（Internet of Things）**  
> 様々なモノ（家電・車・センサー等）がネットワークを通じてサーバやクラウドサービスに接続され、相互に情報交換をする仕組み（Internet of Tools ではない）。

## **1-3. 静的Webサイト vs 動的Webサイト**

Webサイトの配信方式は、固定のHTMLを返す「静的サイト」と、アクセス時にHTMLを動的生成する「動的サイト」に分かれます。

### **【静的サイトと動的サイトの比較】**

| 比較項目 | 静的Webサイト（HTML） | 動的Webサイト（CMS / Webアプリ） |
| --- | --- | --- |
| **コンテンツ生成** | サーバー上のHTMLファイルをそのまま返却。 | **PHP等のサーバサイドプログラムがデータベースと連携**し、利用者の要求に応じてHTMLを都度生成。 |
| **表示内容** | **いつ、誰が見ても同一内容**。 | ログイン状態や検索条件により**表示内容が変化**。 |
| **代表例** | 会社案内、ポートフォリオ、LP | **WordPress**、ECサイト、SNS |
| **メリット** | サーバ負荷が極小、高速、脆弱性が少ない。 | ブラウザから容易に更新可能、高度な機能を提供。 |

## **1-4. 主要サーバソフトウェアとOS・ファイル権限**

Webサイトの裏側では、用途に応じたOSやサーバソフトウェアが役割分担して動作しています。

### **【WebサーバのOSとOSS】**

- **WebサーバのOS：** Webサイトを公開するサーバでは、安定性が高く無償で利用できる **Linux** が広く使われています（企業システム等では **Windows Server** も使用）。
- **OSS（オープンソースソフトウェア）：** ソースコードが公開され、無償利用・改変・再配布が可能なソフトウェア（Linux, Apache, MySQL, PHP, WordPress等）。

### **【主要サーバソフトウェアの種類と役割】**

| サーバの役割 | 代表的ソフトウェア名 | 特徴・実務知識 |
| --- | --- | --- |
| **Webサーバ** | **Apache HTTP Server** | 最も普及しているオープンソースWebサーバ。ディレクトリ単位で設定できる**`.htaccess`**が利用可能。 |
| **Webサーバ** | **Nginx（エンジンエックス）** | 大量同時アクセス処理に特化した軽量・高速サーバ。 |
| **データベースサーバ** | **MySQL / PostgreSQL** | データを表形式で蓄積・検索するリレーショナルデータベース。 |
| **メール送信サーバ** | **Postfix** | メールを宛先へ送信・中継するSMTPサーバ。 |
| **ファイル共有サーバ** | **Samba（サンバ）** | Linux上でWindows標準ファイル共有を実現するソフト。 |

- **ファイルパーミッション（アクセス権限）：** サーバ上のファイルやフォルダに対し、「誰に読取・書込・実行を許可するか」を設定する仕組みです。閲覧権限の設定を誤ると **「403 Forbidden（アクセス拒否）」** の原因になります。

# **2. インターネット通信プロトコルと標準化団体**

## **2-1. OSI基本参照モデルとTCP/IP**

ネットワーク通信は、役割ごとに複数の階層（レイヤー）に分けて定義されています。

### **【OSI基本参照モデル（7階層）】**

国際標準化機構（**ISO**）によって策定された、通信機能を**7つの階層**に分けて定義する参照モデルです（W3C策定ではない）。

| 階層 | 名称 | 主な役割・代表プロトコル |
| :---: | --- | --- |
| 第7層 | **アプリケーション層** | アプリ固有の通信サービス提供（**HTTP**, DNS, FTP, SMTP等） |
| 第6層 | **プレゼンテーション層** | データの表現形式・暗号化・圧縮 |
| 第5層 | **セッション層** | 通信の開始・維持・終了の管理 |
| 第4層 | **トランスポート層** | エンドツーエンドの信頼性確保（TCP, UDP） |
| 第3層 | **ネットワーク層** | 経路選択（ルーティング）とIPアドレッシング（IP） |
| 第2層 | **データリンク層** | 隣接機器間のフレーム伝送（Ethernet, PPP） |
| 第1層 | **物理層** | 電気信号・光信号の変換と伝送 |

### **【TCP/IP 4階層モデルとTCP・UDP】**

現在のインターネットで標準的に使われる4階層の通信モデルです。

| 階層 | 主な役割・機能 | 代表的プロトコル |
| --- | --- | --- |
| **第4層：アプリケーション層** | 各アプリ固有のサービス（Web閲覧、メール送受信等）を提供。 | **HTTP, HTTPS, DNS, FTP, FTPS, SFTP, SMTP** |
| **第3層：トランスポート層** | ポート番号を基に相手アプリへ届ける。 | **TCP**（確認応答あり・高信頼）、**UDP**（高速・リアルタイム） |
| **第2層：インターネット層** | IPアドレスを基にパケットを宛先まで運ぶ（経路選択）。 | **IP**（IPv4, IPv6） |
| **第1層：ネットワークIF層** | 同一回線内の機器間で電気信号や電波を用いて伝送。 | **Ethernet（有線LAN）**、**Wi-Fi（無線LAN）** |

---

## **2-2. 主要プロトコルとデータ保存・接続技術**

**プロトコル**は「通信のルール（手順）」、**ポート番号**は「1台のサーバ内でどのサービス（Webやメール等）へ届けるかを識別する窓口番号」です。

### **【主要な通信プロトコル一覧】**

| プロトコル名 | 役割・特徴 | ポート |
| --- | --- | :---: |
| **HTTP** | Webページをやり取りする基本プロトコル（通信は平文）。 | **80** |
| **HTTPS** | HTTP通信を **SSL/TLSで暗号化**（URLは `https://` で始まる）。 | **443** |
| **DNS** | ドメイン名とIPアドレスを相互変換（名前解決）。 | 53 |
| **FTP** | ファイルを転送するプロトコル（平文のため非推奨）。 | 21 |
| **FTPS** | FTP通信を **SSL/TLSで暗号化** して転送。 | 990等 |
| **SFTP** | **SSHの仕組みを利用**して暗号化ファイル転送（FTPSとは別体系）。 | **22** |

<aside>
💡

**FTPS と SFTP の違い：**
どちらも暗号化通信で安全なファイル転送を行うプロトコルですが、**暗号化の仕組みが異なります**（FTPSはSSL/TLS、SFTPはSSH基盤）。「一方が暗号化されていない」「両者は全く同じプロトコルである」とする誤り選択肢に注意。

</aside>

### **【HTTP認証とネットワーク接続】**

- **Basic認証：** HTTPの認証方式の1つで、ユーザ名とパスワードを **Base64エンコード** して送信します。**ハッシュ化や暗号化ではない**ため盗聴を防ぐことはできず、HTTPSと併用する必要があります。
- **テザリング：** データ通信機能を持ったスマートフォンやタブレットをアクセスポイントとして通信を中継し、PCやゲーム機等の外部機器でインターネットを利用する方法。

### **【ブラウザのデータ保存技術（Cookie と Web Storage）】**

| 技術名 | 特徴・送信の有無 | 主な用途・有効期限 |
| --- | --- | --- |
| **Cookie（クッキー）** | Webサーバからブラウザへ送信・保存され、HTTPリクエストごとに**自動送信**される（約4KB）。 | ログインセッション維持、アクセス解析、広告追跡等。 |
| **LocalStorage** | ブラウザ内に**永続保存**（約5MB）。サーバへの自動送信なし。 | ダークモード設定などの保持。 |
| **SessionStorage** | **タブを閉じるまで有効**（約5MB）。サーバへの自動送信なし。 | フォーム入力の一時下書き等。 |

## **2-3. IPアドレスと主要標準化団体**

### **【IPv4 と IPv6】**

| 比較項目 | IPv4 | IPv6 |
| --- | --- | --- |
| **アドレス長** | **32ビット（固定長）** | **128ビット（固定長）** |
| **表記方法** | ドット（`.`）で区切られた **4つの10進数**（例：`192.0.2.1`） | コロン（`:`）で区切られた **8つの16進数**（例：`2001:db8::1`） |
| **アドレス総数** | 約43億個（枯渇問題） | 約340澗個（実質無制限） |

- **グローバルIP vs プライベートIP：** インターネット上で重複しない唯一の住所が「グローバルIP」、家庭や社内LAN内でのみ使う住所が「プライベートIP」です（ルータの **NAT/NAPT** 機能で相互変換して通信します）。

### **【インターネット主要標準化団体】**

| 団体略称 | 正式名称 | 主な規格・役割 |
| --- | --- | --- |
| **IETF** | Internet Engineering Task Force | 通信プロトコル（TCP/IP, HTTP, DNS）を策定。仕様書は**「RFC」**。 |
| **W3C** | World Wide Web Consortium | Web技術の標準化を推進（**CSS、XML、WCAG**）。創設者はティム・バーナーズ＝リー。 |
| **WHATWG** | Web Hypertext Application Technology Working Group | 現在のHTML標準規格**「HTML Living Standard」**を策定・保守。 |
| **ECMA** | ECMA International | JavaScriptの国際規格**「ECMAScript」**を策定。 |
| **ISO / JIS** | 国際標準化機構 / 日本産業規格 | 国際・国内規格全般（OSI参照モデルやJIS X 8341-3等）。 |

# **3. 情報セキュリティとサイバー攻撃対策**

## **3-1. 情報セキュリティの3大要素（CIA）**

情報セキュリティでは、情報の安全性を保つための基本的な3つの要素（CIA）が定義されています。

| 要素 | 英語名称 | 内容・具体例 |
| --- | --- | --- |
| **機密性** | Confidentiality | 許可された者だけが情報にアクセスできること（パスワード認証、SSL/TLS暗号化等）。 |
| **完全性** | Integrity | 情報が正確であり、不正に改ざん・破壊されていないこと（デジタル署名、改ざん検知等）。 |
| **可用性** | Availability | 必要なときにいつでもシステムやデータを利用できること（冗長化、バックアップ等）。 |

---

## **3-2. マルウェアとサイバー攻撃手法**

### **【代表的なマルウェアの種類と特徴】**

| マルウェア種別 | 動作特性・侵入方法 | 被害内容 |
| --- | --- | --- |
| **コンピュータウイルス** | 他の実行可能ファイルに**寄生して感染**し、宿主を通じて**自己複製**。 | ファイル破壊、データ消去。 |
| **ワーム** | 他ファイルに寄生せず**単独で存在するプログラム**。ネットワークを介して**自己複製して拡散**。 | 回線帯域の枯渇、システム停止。 |
| **トロイの木馬** | 有益なソフトを**装って侵入**し裏で不正動作。**自己複製は行わない**。 | バックドア開設、情報窃取。 |
| **ランサムウェア** | データを**勝手に暗号化**し、復号のために**身代金を要求**。 | 業務停止、データ損失。 |
| **スパイウェア / キーロガー** | 利用者に気づかれずに情報やキー入力を監視・収集し外部へ送信。 | パスワード・個人情報窃取。 |

### **【主なサイバー攻撃手法】**

- **脆弱性（セキュリティホール）：** OSやアプリケーション、ネットワークシステムにおいて、プログラムの不具合や設計ミスが原因で生じたセキュリティ上の弱点や欠陥のこと。

| 攻撃手法 | 特徴・手口 |
| --- | --- |
| **ゼロデイ攻撃** | 修正プログラム（パッチ）が配布される前に脆弱性を突く攻撃。 |
| **DoS / DDoS攻撃** | 大量のアクセスを集中させ、サーバをダウンさせる攻撃（多数端末からの分散型がDDoS）。 |
| **OSコマンド・インジェクション** | 悪意あるリクエストによりWebサーバ上で意図しないOSコマンドを実行させる攻撃。 |
| **SQLインジェクション** | 不正なSQL文を混入させ、DBを不正操作する攻撃（対策：プレースホルダ）。 |
| **クロスサイトスクリプティング（XSS）** | 不正なスクリプトを注入し、他ユーザーのブラウザ上で実行させる攻撃。 |
| **ドライブバイダウンロード** | 改ざんされたWebサイトを閲覧しただけでマルウェアに自動感染させる攻撃。 |
| **フィッシング** | 偽メールから偽サイトへ誘導し、ID・PW・カード番号などを盗む詐欺。 |
| **ソーシャルエンジニアリング** | **人の心理的な隙や不注意を突いて**情報を盗み出す手法（覗き見等）。 |
| **パスワードリスト攻撃** | 他サービスから流出したID・PWの**使い回し**を狙って不正ログインする攻撃。 |

---

## **3-3. セキュリティ対策（SSL/TLS・バックアップ・管理原則）**

### **【通信暗号化とバックアップ対策】**

- **SSL/TLS（Transport Layer Security）：** ウェブサイトの通信を暗号化し、データの盗聴や改ざんを防ぐ技術です。
  - **SSL/TLS証明書の役割と期限切れリスク：** 通信の暗号化に加えて「サイトの真正性（なりすまし防止）」を証明します。証明書の有効期限が切れるとブラウザに警告画面が表示され、**ユーザの信頼を失う可能性**があります。
- **バックアップ戦略の「321ルール」：** 可用性を確保するため、重要なデータは **「3つのコピー」** を作り、**「2種類の異なる媒体」** に保存し、**「1つはオフサイト（別拠点・クラウド等）に保管」** することが推奨されます。

### **【セキュリティ管理原則と認証・法規】**

- **多要素認証（MFA）：** 「**知識情報**（パスワード等）」「**所持情報**（スマホSMS・ワンタイムパスワード等）」「**生体情報**（指紋・顔等）」のうち異なる2つ以上を組み合わせた強固な本人確認。
- **最小権限の原則：** ユーザアカウントやプログラムの権限を最小限に設定しておくことで、セキュリティリスクを低減できます。
- **不要ファイルの削除：** Webサーバ内に不要になったファイルを放置せず削除することも、情報漏洩を防ぐ重要なセキュリティ対策の1つです。
- **サイバーセキュリティ基本法：** サイバーセキュリティに関する施策を総合的かつ効果的に推進するため、基本理念および国の責務、戦略、基本的施策等を規定した法律。

# **4. Webフロントエンドスクリプト（JavaScript / DOM基礎）**

## **4-1. 基本仕様と配列・文字列**

- **`<script>` タグ：** 外部JavaScriptファイル（`.js`）は、1つのHTML文書内に**複数読み込むことが可能**です。
- **変数宣言と文字列結合：** `const`（再代入不可の定数）、`let`（再代入可能な変数）、`var`（旧規格）。`+` 演算子で文字列を連結できます（`===` は型の一致まで判定する厳密等価演算子）。
- **配列のインデックス：** 配列の添字（要素番号）は必ず **「0」から始まります**（`array[0]` が1番目、`array[1]` が2番目）。

```javascript
// 配列の例
var array = ["a", "b", "c"];
console.log(array[1]); // 出力: "b"（0番目が"a", 1番目が"b"）

// 文字列結合の例
let title = "Web";
title = title + "Design";
console.log(title); // 出力: "WebDesign"
```

## **4-2. DOM操作とイベント処理**

JavaScriptからHTML要素を取得し、ユーザーの操作（イベント）に応じて表示やスタイルを動的に書き換えることができます。

```html
<main id="content">Webサイトのメインコンテンツ</main>
<button onclick="fontLarge()">大きく表示</button>

<script>
  const main = document.querySelector("main");

  function fontLarge() {
    document.getElementById("content").style.fontSize = "2em"; // CSSのfont-size操作
  }

  // ドロップダウンの変更イベント取得例
  const select = document.getElementById("select");
  select.addEventListener("change", (event) => {
    const selectedValue = event.target.value;
  });
</script>
```

- **要素の取得：** `document.querySelector("セレクタ")`、`document.getElementById("id名")`。
- **スタイル・クラス操作：**
  - `要素.style.display = "none"`（非表示）、`要素.style.fontSize = "2em"`（CSSのハイフン区切りプロパティはキャメルケースで記述）。
  - `要素.classList.add("クラス名")` / `remove()` / `toggle()`（クラスの追加・削除・切り替え）。
- **イベントとイベントハンドラ：** `onclick="関数名()"` のようにイベント発生時の処理を指定するHTML属性を**イベントハンドラ**と呼びます（`addEventListener("change", ...)` のようにJS側で指定する場合は `"on"` を付けない）。
