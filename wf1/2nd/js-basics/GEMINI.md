# 講義教材（Markdown）作成・編集ルール

## 1. 文末の表記ルール
- 文の終わりに「！」（全角感嘆符）や「!」（半角感嘆符）は一切使用しないこと。
- 見出し、本文、リスト、コールアウトを含め、文末は「。」（句点）または通常の体言止め・語尾で記述すること。
- ※ プログラムコード内の構文やMarkdown構文としての記号（画像記法等）は除く。

## 2. サンプル・練習問題のCSS作成方針
- JavaScriptの学習に集中できるよう、CSSのセレクタは最小限に抑え、コード量を短く保つこと。
- ただし、ブラウザ上での十分な視認性・余白・レイアウトは担保すること。
- JavaScriptから操作・取得するIDやクラス名（`.is-active` 等）は厳密に維持すること。

## 3. 練習問題・課題の設計方針
- 練習問題の見出しはナンバリング（「練習1」「練習2」など）を行わず、「`## ⭐︎ 練習：〜`」（発展演習は「`## ⭐︎ 練習（発展演習）：〜`」）で統一すること（問題の前後入替や追加に対応しやすくするため）。
- 「仕様・要件」の段階では、受講生に自力でロジックを考えさせるため、完成形のJavaScriptコード（メソッド呼び出しや計算式など）を直接書かず、達成すべき動作やロジックを言葉で説明すること。
- つまずきやすいポイントや自力での想起が難しい構文は、仕様の文章内ではなく「💡 **ヒント**」（コールアウト等）で適切に補完・誘導すること。
- 正解コードは必ず折りたたみトグル（Markdownでは `- 正解のソースコード...` 等から変換される `<details>`）内に配置し、自力で考えた後に確認できるようにすること。

## 4. 演習フォルダの構成と複製ワークフロー
- 単元開始時は、最初の演習用フォルダ（例: `practice01`）を作成し、そこに `index.html`、`style.css`、`main.js` を配置して演習を進めること。
- 単元の途中でUIや操作対象が大きく変わる場合（例: 第4章など）は、手前のフォルダ（`practice01`）を丸ごと複製して `practice02` にリネームし、中身を置き換えて進める構成とすること（過去の演習コードを破壊しないため）。
- 最後の総合課題では、直前の演習フォルダを複製して課題用フォルダ（例: `photoGallery`）にリネームして実装すること。
- 単元終了時には、複製した各ステップのフォルダがすべて揃った状態で提出（GitHubへコミット＆プッシュ）する案内とすること。

## 5. Notion連携ルール
- 講義資料をNotionへ同期する際は、`scripts/sync_lecture_to_notion.py` を使用して全自動で反映すること。
- H1の先頭スペース保持（`# \ `）や余白の相殺ルールを崩さないこと。
