### 第1問 【バグ検出：代入演算子と厳密等価演算子の違い】
- **問題文**:
変数 score が 100 と等しいかどうかを判定するために、以下の if 文を書いたところ、score が 50 なのに「満点です！」と表示されてしまいました。このバグの原因と正しい修正方法として適切なものはどれでしょうか？

```javascript
let score = 50;

if (score = 100) {
  console.log('満点です！');
}
```

- **選択肢**:
if 文の中では let で宣言した変数を使えないため、const score = 50; に修正する
イコール1つ（=）は「比較」ではなく「代入（score に 100 を入れる命令）」になってしまうため、厳密に等しいか比較する ===（イコール3つ）に修正する
数値の比較にはイコールを使えないため、score >= 100 && score <= 100 に修正する
100 をシングルクォーテーションで囲み、score = '100' に修正する

- **正解**: イコール1つ（=）は「比較」ではなく「代入（score に 100 を入れる命令）」になってしまうため、厳密に等しいか比較する ===（イコール3つ）に修正する
- **解説**:
JavaScriptにおいて =（イコール1つ）は「右の値を左の変数に代入する」という命令です。if (score = 100) と書くと、score に 100 が代入され、その値（100）が条件式として常に true 扱いになってしまいます。左右が等しいか比較するときは、値とデータ型の両方が一致するか調べる厳密等価演算子 === を必ず使用します。

### 第2問 【バグ検出：if ... else if の判定順序】
- **問題文**:
テストの点数（score）が 90点以上なら「評価S」、70点以上なら「評価A」、それ未満なら「評価B」と出力したいのですが、以下のコードを実行すると 95点なのに「評価A」と出力されてしまいました。その理由として正しいものはどれでしょうか？

```javascript
const score = 95;

if (score >= 70) {
  console.log('評価A');
} else if (score >= 90) {
  console.log('評価S');
} else {
  console.log('評価B');
}
```

- **選択肢**:
else if は最大1回しか使えず、else と同時に書くことができない構文だから
if 文は上から順番に判定され、最初の score >= 70 に合致した時点でそのブロックが実行され、以降の else if は無視されるから
const で宣言した変数は else if の条件式の中で参照できないから
>= 演算子は90以上の数値を正しく比較できないから

- **正解**: if 文は上から順番に判定され、最初の score >= 70 に合致した時点でそのブロックが実行され、以降の else if は無視されるから
- **解説**:
if ... else if 文は上から順番に評価され、最初に条件が true になったブロックだけが実行されて処理を抜けます。95点は最初の score >= 70 を満たしてしまうため、下の score >= 90 には到達しません。数値の範囲を判定するときは、厳しい条件（この場合は 90点以上）から先に書くのが鉄則です。

### 第3問 【定着度：論理演算子（AND・OR・NOT）】
- **問題文**:
「会員である（isMember が true）」かつ「購入金額が 5000円以上（total >= 5000）」という**両方の条件を同時に満たすとき**だけ処理を実行したいです。if 文の条件式として正しいものはどれでしょうか？

- **選択肢**:
if (isMember || total >= 5000)
if (isMember && total >= 5000)
if (!isMember && total >= 5000)
if (isMember & total => 5000)

- **正解**: if (isMember && total >= 5000)
- **解説**:
左右の条件が「両方とも true のときだけ true になる（かつ / AND）」を表す論理演算子は && です。|| は「どちらか一方でも true なら true（または / OR）」、! は「条件の反転（否定 / NOT）」を表します。

### 第4問 【推論力：三項演算子（条件演算子）の評価】
- **問題文**:
以下のコードを実行したとき、Consoleに出力される値として正しいものはどれでしょうか？

```javascript
const isOpen = false;
const buttonText = isOpen ? '閉じる' : '開く';

console.log(buttonText);
```

- **選択肢**:
閉じる
開く
false
true

- **正解**: 開く
- **解説**:
三項演算子は「条件式 ? trueのときの値 : falseのときの値」という構文で2択の値を切り替えます。今回 isOpen は false なので、コロン（:）の後ろにある '開く' が変数 buttonText に代入されます。

### 第5問 【バグ検出：イベントリスナーと変数の宣言位置（スコープ）】
- **問題文**:
ボタンをクリックするたびにカウントを1ずつ増やして表示したいのですが、以下のコードでは何度ボタンをクリックしても画面の数字が「1」から増えません。原因として正しいものはどれでしょうか？

```javascript
const btn = document.getElementById('btn');
const countDisplay = document.getElementById('count');

btn.addEventListener('click', () => {
  let count = 0;
  count++;
  countDisplay.textContent = count;
});
```

- **選択肢**:
count++ ではなく count + 1 と書かなければ1増えないから
let count = 0; をクリックイベントの関数の中に書いているため、クリックするたびに毎回 0 にリセットされてしまうから
textContent には数値を代入することができないから
addEventListener の第1引数が 'click' ではなく 'count' でなければならないから

- **正解**: let count = 0; をクリックイベントの関数の中に書いているため、クリックするたびに毎回 0 にリセットされてしまうから
- **解説**:
イベントリスナーの { } の中に let count = 0; を書いてしまうと、ボタンがクリックされるたびに変数が新しく 0 で作り直されてしまいます（0 → 1 になる処理が毎回繰り返される）。クリック回数の記録やゲームのHPなど、イベントをまたいで保持し続けたい変数は、必ずイベントリスナーの「外側」で宣言する必要があります。

### 第6問 【定着度：クラス操作と属性操作の役割の違い】
- **問題文**:
JavaScriptにおける「クラス操作（classList）」と「属性操作（getAttribute / setAttribute など）」の使い分けとして、最も適切な説明はどれでしょうか？

- **選択肢**:
クラス操作はHTMLタグの削除に使い、属性操作はCSSファイルの読み込みに使う
クラス操作はCSSと連携して「見た目（デザインや状態スタイル）」を切り替えるために使い、属性操作は画像URL・リンク先・入力タイプ・ボタンの無効化など要素の「機能や情報」を切り替えるために使う
クラス操作は <div> タグにしか使えず、属性操作は <img> タグと <a> タグにしか使えない
現在では属性操作は廃止されており、画像URLやリンク先の変更もすべて classList で行うのが標準である

- **正解**: クラス操作はCSSと連携して「見た目（デザインや状態スタイル）」を切り替えるために使い、属性操作は画像URL・リンク先・入力タイプ・ボタンの無効化など要素の「機能や情報」を切り替えるために使う
- **解説**:
色やアニメーションなどの「見た目（スタイル）」の変更は classList でCSSクラスを付け外しして行い、画像の src、リンクの href、フォームの type や disabled など要素自体の「機能・データ」を変更するときは属性操作（getAttribute / setAttribute / removeAttribute）を使います。

### 第7問 【定着度：getAttributeとsetAttributeの基本構文】
- **問題文**:
画像要素 viewImg（`<img id="view-img" src="day.jpg" alt="昼の風景">`）の画像を `"night.jpg"` に変更したいです。属性の値を新しく設定・上書きするコードとして正しいものはどれでしょうか？

- **選択肢**:
viewImg.getAttribute('src', 'night.jpg');
viewImg.setAttribute('src', 'night.jpg');
viewImg.setAttribute('src="night.jpg"');
viewImg.addAttribute('src', 'night.jpg');

- **正解**: viewImg.setAttribute('src', 'night.jpg');
- **解説**:
属性の値を設定・上書きするには setAttribute('属性名', '新しい値') を使用します。第1引数に属性名（'src'）、第2引数に設定したい値（'night.jpg'）を渡します。getAttribute() は現在の属性値を「取得（読み取り）」するためのメソッドです。

### 第8問 【定着度：removeAttributeによるボタンの有効化】
- **問題文**:
HTML上で `<button id="post-btn" disabled>投稿する</button>` のように disabled 属性が付いて無効化（押せない状態に）されているボタンがあります。JavaScriptでこのボタンの disabled 属性を取り除き、再びクリックできるようにするコードはどれでしょうか？

- **選択肢**:
postBtn.removeAttribute('disabled');
postBtn.deleteAttribute('disabled');
postBtn.classList.remove('disabled');
postBtn.getAttribute('disabled', false);

- **正解**: postBtn.removeAttribute('disabled');
- **解説**:
HTML要素から指定した属性を完全に削除するには removeAttribute('属性名') を使用します。disabled 属性は、タグにその属性が存在しているだけでボタンが無効化されるため、removeAttribute('disabled') で属性自体を取り除くことでボタンが有効化（押せる状態に）されます。

### 第9問 【推論力：パスワード表示切り替えのロジック】
- **問題文**:
パスワード入力欄（passwordInput）の現在の type 属性を調べ、`'password'`（伏せ字）なら `'text'`（平文表示）に切り替え、そうでなければ `'password'` に戻す処理を実装します。コード内の【 空欄A 】と【 空欄B 】に入るメソッドの組み合わせとして正しいものはどれでしょうか？

```javascript
togglePasswordBtn.addEventListener('click', () => {
  // 現在の type 属性の値を取得する
  const currentType = passwordInput.【 空欄A 】('type');

  if (currentType === 'password') {
    // type 属性を 'text' に変更する
    passwordInput.【 空欄B 】('type', 'text');
  } else {
    // type 属性を 'password' に戻す
    passwordInput.【 空欄B 】('type', 'password');
  }
});
```

- **選択肢**:
【 空欄A 】: getAttribute ／ 【 空欄B 】: setAttribute
【 空欄A 】: setAttribute ／ 【 空欄B 】: getAttribute
【 空欄A 】: hasAttribute ／ 【 空欄B 】: removeAttribute
【 空欄A 】: querySelector ／ 【 空欄B 】: classList.add

- **正解**: 【 空欄A 】: getAttribute ／ 【 空欄B 】: setAttribute
- **解説**:
まず現在の type 属性が何になっているかを調べる（取得する）ために getAttribute('type') を使います（空欄A）。その後、if 文の判定結果に応じて新しい値を設定（上書き）するために setAttribute('type', '...') を使います（空欄B）。

### 第10問 【定着度：リアルタイム文字数カウンター（inputイベントとvalue.length）】
- **問題文**:
テキスト入力欄（commentInput）にユーザーが文字を打ち込むたびに、リアルタイムで現在の入力文字数を数えて表示したいです。このとき使うべき「イベント名」と「文字数を取得する記述」の正しい組み合わせはどれでしょうか？

- **選択肢**:
イベント名：'click' ／ 文字数の取得：commentInput.textContent.length
イベント名：'input' ／ 文字数の取得：commentInput.value.length
イベント名：'scroll' ／ 文字数の取得：commentInput.getAttribute('length')
イベント名：'type' ／ 文字数の取得：commentInput.count

- **正解**: イベント名：'input' ／ 文字数の取得：commentInput.value.length
- **解説**:
フォームの入力欄に1文字打ち込んだり消したりするたびにリアルタイムで発火するイベントは 'input' です。また、<input> 要素に入力されている文字列は .value プロパティで取得でき、その後ろに .length を繋げる（commentInput.value.length）ことで現在の文字数を数値として取得できます。
