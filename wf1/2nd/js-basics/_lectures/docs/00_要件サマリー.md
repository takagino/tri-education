# その他含めたい内容
- カスタムデータ属性
- オブジェクトと配列を組み合わせたデータ管理
理由：スライドショーの画像リストや、カテゴリーの情報を const slides = [{ src: 'img1.jpg', text: '説明' }, ...] のようにオブジェクトの配列として定義させるため。実務的なデータ構造を学ぶ絶好のサンプルになります。
- テンプレートリテラル（バッククォート ${} の使用）
理由：スライドショーの丸ボタンなどをJavaScriptで自動生成する際、昔ながらの + を使った文字列結合ではなく、現代的で可読性の高いテンプレートリテラルを出力させるため。
- イベントオブジェクト（e.preventDefault() や e.target）
理由：フォームのバリデーション時の送信キャンセルや、クリックした要素の特定に必須となるため。
- defer または DOMContentLoaded の明記
理由：HTML要素が読み込まれる前にJavaScriptが実行されてエラーになるのを防ぐ、現場の基本作法をコードに反映させるため。

# 作成するWebサイトの概要
授業で学んだ以下のUIコンポーネントを全て盛り込んだ、架空のコーポレートサイト（またはサービスサイト）のLPを作成してください。

- ハンバーガーメニュー： スマホサイズでのメニュー開閉。
- 文字サイズ変更ボタン： ページ全体の文字サイズを「小・標準・大」などに切り替える機能。
- アコーディオン： 「よくある質問」などで使用する開閉パネル。
- スライドショー： ヒーローヘッダー等の画像切り替え。自動再生・ホバーで停止・次へ/前へボタン・丸ボタンナビゲーション（枚数に応じて自動生成）を実装。
- モーダルウィンドウ： 画像の拡大表示、またはお問い合わせフォームのポップアップ。
- カテゴリーによる記事の絞り込み表示
- 日付と時計の表示（今日の日付と現在時刻を表示）
- ランダムな背景画像（body要素の背景画像をランダムに変更）
- 外部サイトに自動的に「_blank」を付与
- トップへ戻るボタン（スクロール量に応じた表示切替）
- スクロールに連動した要素のフェードイン
- お問い合わせフォームの簡易バリデーション（入力チェック）
- パスワードの表示/非表示切り替え

# 技術スタックとコーディングルール
学生が自力でコードを読み解けるよう、以下のルールを厳守してください。

- 使用言語： HTML5、CSS3、Vanilla JavaScript。
- 禁止事項： jQueryやReact等のライブラリは一切使用不可。三項演算子の多用、アロー関数の極端な省略、mapやfilterなどの高度な配列メソッドの使用は避けてください（これらは2年生で学習します）。
- JavaScriptの構文制限： let / const、if / switch、for / while、addEventListener、setInterval / setTimeout、parentElement / nextElementSibling などの基本的なDOMトラバーサルを中心に構成してください。
- UI状態の管理： JavaScriptで style.display = 'none' などを直接操作するのではなく、HTML要素に is-active や is-open などのクラスを付け外し（classList.toggle 等）することで、CSS側で表示・非表示やアニメーションを制御してください。
- CSS設計： BEMの命名規則に準拠し、保守性の高いクラス名にしてください。
- コメント： 各UIコンポーネントの処理ブロックの先頭に、何をしている処理なのか日本語で丁寧なコメントを記述してください。

# 資料作成オペレーション（AIとの制作フロー）

各単元のNotion講義資料を作成する際は、以下のステップで進めます。

### 1. 参照と要件確認
- `_lectures/docs/00_カリキュラム設計書.md` から、該当単元の「目標・扱う文法キーワード・メソッド・演習UI」を確認する。
- `_lectures/docs/00_要件サマリー.md` のコーディングルール（ライブラリ不使用、構文制限、BEM等）を遵守する。

### 2. ファイルの作成と命名規則
- 作成先：`_lectures/` 直下
- 命名規則：`{2桁の単元番号}_{カリキュラム設計書の単元名}.md`
  - 例：`02_DOMの取得と要素の書き換え.md`
  - 例：`03_イベント処理とクラス操作によるUI切替.md`
- **下書き（draft）ファイルは作らず、直接このファイルをチャット上で推敲・更新していく**（バージョン管理はGitで行う）。

### 3. フォーマット・スタイルの統一
先行して完成した `_lectures/01_基礎知識・変数・データ型.md` の構成を踏襲します。
- **冒頭ナビゲーション**: 全単元へのリンク一覧（Notionのページリンク）
- **本日のゴール**: そのコマで達成する目標（箇条書き3〜5点）
- **解説ブロック**: 丁寧なたとえ話、コード例、良い例・悪い例の比較
- **Notionコールアウト風の補足**: `<aside> 💡 ... </aside>` によるワンポイント解説や現場のTips
- **体験・演習（ハンズオン）**: 学生が実際にコードを書いてブラウザで確認するステップ形式
- **まとめ & 次回予告**: 学習の振り返りと次単元への接続

### 4. 学生用フォルダ（コード）との連携
- 講義資料内で扱うハンズオンや課題コードの完成版・スターターコードは、必要に応じて対応する学生配布用フォルダ（例：`02_dom/`）内に配置・コミットする。

# 年度更新オペレーション（次年度への移行）

2026年度の授業が完了し、次年度（2027年度）の教材作成を開始する際は、以下の手順で一括アーカイブします。

1. `_lectures/` の中身（テキストおよびdocs）を、そのまま `_backup/2026-lecture/` に移動する。
2. 新たな `_lectures/` ディレクトリを作成し、新年度のカリキュラム作成を開始する。
これにより、常に「現役の最新講義データは `_lectures/` にある」状態を維持できます。
