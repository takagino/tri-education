### 第1問 【定着度：classListの引数指定とドットの有無】
- **問題文**:
HTML要素 btn にクラス is-active を追加したいです。classList.add() の正しい書き方はどれでしょうか？

- **選択肢**:
btn.classList.add('.is-active');
btn.classList.add('is-active');
btn.classList.add('class="is-active"');
btn.classList.add('#is-active');

- **正解**: btn.classList.add('is-active');
- **解説**:
querySelector ではCSSセレクタとしてドット（.is-active）を付けましたが、classList は「クラス属性を操作するための専用命令」であるため、ドットは不要で純粋なクラス名（'is-active'）だけを指定します。ドットを付けてしまうと、.is-active というピリオド付きの意図しないクラス名が付与されてしまいます。

---

### 第2問 【定着度：classList.toggleの挙動】
- **問題文**:
要素 menu に対して menu.classList.toggle('is-open'); を実行しました。このメソッドの動作として正しいものはどれでしょうか？

- **選択肢**:
常に 'is-open' クラスを追加する
常に 'is-open' クラスを削除する
'is-open' クラスが付いていなければ追加し、付いていれば削除する（反転切り替え）
'is-open' クラスの文字列を大文字（IS-OPEN）に変換する

- **正解**: 'is-open' クラスが付いていなければ追加し、付いていれば削除する（反転切り替え）
- **解説**:
toggle（トグル）は「反転切り替え」を意味します。そのクラスが付いていない状態なら追加（add）し、すでに付いている状態なら削除（remove）します。スイッチのON/OFFやメニューの開閉など、2つの状態を交互に切り替えるUIに最も頻繁に使われます。

### 第3問 【推論力：classList.containsの戻り値】
- **問題文**:
以下のHTMLとJavaScriptを実行したとき、Consoleに出力される内容として正しいものはどれでしょうか？

```html
<!-- HTML -->
<button id="btn" class="btn is-active">ボタン</button>
```

```javascript
// JavaScript
const btn = document.getElementById('btn');
console.log(btn.classList.contains('is-active'));
```

- **選択肢**:
"is-active"
true
false
1

- **正解**: true
- **解説**:
classList.contains() は、指定したクラスが要素に付いているかどうかを確認し、結果を真偽値（true または false）で返します。このボタンには最初から is-active クラスが付与されているため、結果は true となります。

### 第4問 【定着度：状態クラス（State Class）の設計思想】
- **問題文**:
Web制作において、メニューが開いている状態やボタンがアクティブな状態を表すクラスを「状態クラス（State Class）」と呼びます。実務の慣例として、クラス名の先頭に付与される推奨接頭辞（プレフィックス）はどれでしょうか？

- **選択肢**:
has-（例: .has-menu）
is-（例: .is-open, .is-active）
on-（例: .on-click）
do-（例: .do-open）

- **正解**: is-（例: .is-open, .is-active）
- **解説**:
Webデザイン設計において、現在の動的な状態を表すクラスには「〜な状態である」を意味する be動詞の is- を付ける命名規則（例: .is-active, .is-open, .is-visible）が業界標準として広く定着しています。これにより、通常の静的なデザイン用クラスとJavaScriptで制御する動的な状態クラスが一目で判別できます。

### 第5問 【定着度：element.styleとCSSクラス操作の役割分担】
- **問題文**:
Web制作の実務において、JavaScriptから直接 element.style で色や配置を変更するよりも、「CSSにあらかじめクラスを定義しておき、classList で付け外しする」手法が推奨される理由として**適切でないもの**はどれでしょうか？

- **選択肢**:
element.style を使うとHTMLタグにインラインスタイルが直接書き込まれ、CSSの優先順位が強すぎて外部CSSでの上書きやレスポンシブ対応が難しくなるため
JavaScriptのコード内にスタイル情報（色や余白など）が散らかり、保守性が低下するため
element.style を使った場合、CSSのトランジションアニメーション（transition）を適用することが不可能になるため
「見た目や装飾はCSS」「状態の変化はJavaScript」と設計上の役割を綺麗に分離するため

- **正解**: element.style を使った場合、CSSのトランジションアニメーション（transition）を適用することが不可能になるため
- **解説**:
element.style で変更した場合でもCSSの transition は有効に動作します（不可能なわけではありません）。クラス操作が推奨される本質的な理由は、インラインスタイルの詳細でJavaScriptコードが長文化・煩雑化するのを防ぎ、スタイル設計（CSS）と振る舞い（JS）の役割分担を保つためです。

### 第6問 【定着度：スクロール量の取得】
- **問題文**:
現在のWebページが上から垂直方向に何ピクセルスクロールされているかを数値（px）で取得できるプロパティとして正しいものはどれでしょうか？

- **選択肢**:
window.scrollY
document.scrollTop
window.scrollWidth
element.scrollHeight

- **正解**: window.scrollY
- **解説**:
ブラウザの垂直スクロール量（現在ページが上から何pxスクロールされているか）は、window.scrollY（または window.pageYOffset）で数値として取得できます。

### 第7問 【バグ検出：リロード直後のスクロール連動スタイル】
- **問題文**:
スクロール量に合わせてボタンを回転させる処理を実装しました。

```javascript
window.addEventListener('scroll', () => {
  btn.style.transform = `rotate(${window.scrollY}deg)`;
});
```

ページを途中までスクロールした状態でブラウザをリロード（再読み込み）したところ、スクロール途中から画面が始まっているのに、ボタンの回転角度が初期状態（0度）に戻ってしまいました。この原因として最も適切なものはどれでしょうか？

- **選択肢**:
リロード直後は JavaScript がブラウザ側で一時的に無効化されるため
'scroll' イベントはユーザーが実際にスクロール操作を行った瞬間にしか発火しないため、リロード直後は一度も処理が動いていないから
window.scrollY はページ最上部（0px）にいるときしか取得できないプロパティだから
rotate() に指定できる数値の限界（360度）を超えてエラーになったから

- **正解**: 'scroll' イベントはユーザーが実際にスクロール操作を行った瞬間にしか発火しないため、リロード直後は一度も処理が動いていないから
- **解説**:
'scroll' イベントリスナーの中身は、あくまで「ユーザーが画面をスクロールした瞬間」にしか実行されません。リロード直後はまだスクロール操作が一度も行われていないため、イベントリスナー内のコードが動かず初期スタイルになってしまいます。これを防ぐには、ページ全体の読み込み完了時に動く 'load' イベントでも同様のスタイル適用処理を実行する必要があります。

### 第8問 【推論力：ブラウザ幅のリアルタイム監視】
- **問題文**:
ブラウザのウィンドウ幅（横幅ピクセル数）の変化をリアルタイムに監視・取得したいとき、組み合わせるべき「イベント名」と「プロパティ」の正しいペアはどれでしょうか？

- **選択肢**:
イベント：'change' ／ プロパティ：document.width
イベント：'resize' ／ プロパティ：window.innerWidth
イベント：'scale' ／ プロパティ：window.outerWidth
イベント：'screen' ／ プロパティ：window.screenWidth

- **正解**: イベント：'resize' ／ プロパティ：window.innerWidth
- **解説**:
ブラウザウィンドウのサイズが変更された瞬間に発生するイベントは 'resize' です。また、現在開いているブラウザの内側の横幅（ピクセル数）は window.innerWidth で取得できます。

### 第9問 【定着度：classList.removeの安全な挙動】
- **問題文**:
HTML要素 btn にクラス 'is-active' が**最初から付いていない状態**で、btn.classList.remove('is-active'); を実行しました。このときの動作として正しいものはどれでしょうか？

- **選択肢**:
JavaScriptのエラー（NotFoundError）が発生して以降の処理が停止する
HTML上のすべてのクラスが強制的に初期化（削除）される
エラーにはならず、安全に無視されて何も起こらない
null が返され、ページ全体がリロードされる

- **正解**: エラーにはならず、安全に無視されて何も起こらない
- **解説**:
classList.remove() は、指定したクラスが要素に付いていない場合でもエラーを発生させず、安全に無視されます。そのため、事前に contains() でクラスの有無をチェックしなくても、安全に削除処理を記述できます。

### 第10問 【推論力：クラス反転と状態判定のメソッド組み合わせ】
- **問題文**:
ボタンをクリックするたびにクラス 'is-active' を交互に付け外し（反転）させ、現在そのクラスが付いているかどうかに応じてボタンの表示テキストを切り替えたいです。コード内の【 空欄A 】と【 空欄B 】に入るメソッドの組み合わせとして正しいものはどれでしょうか？

```html
<!-- HTML -->
<button id="btn" class="btn">通常状態</button>
```

```javascript
// JavaScript
const btn = document.getElementById('btn');

btn.addEventListener('click', () => {
  // クリックするたびに is-active を反転切り替え
  btn.classList.【 空欄A 】('is-active');

  // is-active が付いているかどうかを確認して文字を分岐
  if (btn.classList.【 空欄B 】('is-active')) {
    btn.textContent = 'アクティブ状態';
  } else {
    btn.textContent = '通常状態';
  }
});
```

- **選択肢**:
【 空欄A 】: toggle ／ 【 空欄B 】: contains
【 空欄A 】: add ／ 【 空欄B 】: contains
【 空欄A 】: toggle ／ 【 空欄B 】: has
【 空欄A 】: change ／ 【 空欄B 】: includes

- **正解**: 【 空欄A 】: toggle ／ 【 空欄B 】: contains
- **解説**:
クラスを交互に付け外し（反転切り替え）する命令は **toggle()** です（空欄A）。また、要素がそのクラスを持っているかどうかを判定して真偽値（true / false）を返し、if 文の条件式として利用できる命令は **contains()** です（空欄B）。（※classList に has や includes、change というメソッドは存在しません）
