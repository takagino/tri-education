# その他含めたい内容（および選定理由）

- **モダンCSS関数（`clamp()`, `min()`, `max()`, `calc()`）の徹底活用**
  - **理由**: 画面幅ごとにメディアクエリを細かく記述する従来手法から脱却し、1行で滑らかに拡大縮小するFluid Typography（流体タイポグラフィ）やレイアウトを構築できる、現代の実務標準スキルであるため。
- **Modern Sass: `@use` と `@forward` によるモジュール管理**
  - **理由**: 旧来の `@import` はSass公式で非推奨（Deprecated）となっており、グローバル名前空間汚染のない `@use "..." as *;` などの最新モジュール構文を身につけさせるため。
- **CSS Grid の `subgrid` 機能**
  - **理由**: カードUI等で「タイトル行の高さ」「説明文の高さ」を親のグリッドに合わせて綺麗に揃える現場の必須テクニックであり、主要モダンブラウザで完全対応した今こそ教えるべき機能であるため。
- **次世代画像フォーマット（WebP/AVIF）と `<picture>` 要素**
  - **理由**: 表示パフォーマンス（LCP）改善の要であり、デザイナー出身者が直面する「画質とファイルサイズの両立」の最適解をコードレベルで理解させるため。
- **セマンティクスと `:focus-visible` によるアクセシビリティ（a11y）対応**
  - **理由**: 単にdivで組む悪癖を脱し、キーボード操作やスクリーンリーダーに配慮したインクルーシブなWeb制作の基本作法を1年生のうちに体得させるため。
- **GSAP（GreenSock）および ScrollTrigger プラグイン**
  - **理由**: Web制作・クリエイティブエージェンシーの現場でデファクトスタンダードとなっている強力なアニメーションライブラリであり、CSSのみでは難しいスクロール連動演出を無理なく直感的に実装できるため。

# 作成するWebサイトの概要（演習・最終課題）

授業で学んだ「BEM・Sass・FLOCSS・モダンレスポンシブ・CSS Grid・GSAP・アクセシビリティ・パフォーマンス」の集大成として、**架空のデザインスタジオ（またはアーキテクチャ事務所・クリエイティブブランド）の公式Webサイト（トップページ＋下層1ページ相当）**をマークアップします。

### 必須要件・実装コンポーネント一覧:
1. **設計・アーキテクチャ**:
   - FLOCSSに基づいたSassディレクトリ設計（Foundation, Layout, Object[Component, Project, Utility]）。
   - BEM（MindBEMding記法）に準拠した破綻のないクラス命名。
2. **レスポンシブ & タイポグラフィ**:
   - rem設計（ルート基準フォントサイズ設定）。
   - `clamp()` を用いたFluid Typography（画面幅に応じて滑らかに可変するフォントサイズ・余白）。
   - スマホ（〜767px）、タブレット（768px〜1023px）、PC（1024px〜）対応。
3. **レイアウト**:
   - Flexbox（1次元レイアウト）と CSS Grid（2次元非対称レイアウト・`subgrid` を含むカード整列）の適材適所の使い分け。
4. **アニメーション & インタラクション（GSAP）**:
   - ファーストビューの洗練された要素登場アニメーション（GSAP Timeline）。
   - スクロール連動のフェードイン・画像パララックス・スクラブ演出（ScrollTrigger）。
   - ボタンやリンクの自然なマイクロインタラクション。
5. **品質・アクセシビリティ・パフォーマンス**:
   - セマンティックなHTML構造（`header`, `main`, `section`, `article`, `nav`, `footer`）。
   - 次世代画像（WebP）と `<picture>`、`loading="lazy"` の適切な実装。
   - LighthouseのPerformanceおよびAccessibilityスコアで **90点以上** を目標値とする。
6. **バージョン管理**:
   - GitHubリポジトリによる管理、Gitコミット履歴の整理、GitHub Pagesでのプレビュー公開。

# 技術スタックとコーディングルール

学生がプロの現場に直結するコード品質を身につけられるよう、以下のルールを適用します。

- **使用言語・ツール**:
  - HTML5（セマンティックマークアップ）
  - CSS3 / SCSS（Dart Sass）
  - JavaScript（ES6+）: GSAP 3.x, ScrollTrigger プラグイン
  - バージョン管理: Git / GitHub
  - エディタ環境: Visual Studio Code（`settings.json` による保存時自動整形、必須拡張機能: Live Preview, Live Sass Compiler 等）
- **CSS設計ルール**:
  - **FLOCSS**: `foundation/`, `layout/`, `object/component/`, `object/project/`, `object/utility/` にファイルをパーシャル分割（`_*.scss`）。
  - **BEM命名規則**:
    - Block: `.c-card`, `.p-hero`, `.l-header`（プレフィックス併用）
    - Element: `__item`, `__title`, `__body`
    - Modifier: `--primary`, `--active`, `is-active`（状態クラス）
  - **Sass記法**:
    - 旧 `@import` の禁止（`@use` を使用）。
    - ネストの深さは原則「最大3階層まで」（ネストの深すぎによる特異度・可読性低下を防止）。
- **禁止事項**:
  - CSSフレームワーク（Tailwind CSS, Bootstrap等）の使用禁止（基礎の自力実装力を養うため）。
  - jQueryの使用禁止（Vanilla JSまたはGSAPを使用）。
  - `!important` の原則禁止（Utilityクラスや一部オーバーライド時のみ例外許可）。
  - インラインスタイルの直接記述禁止。
- **コメント作法**:
  - SCSSファイル先頭に各コンポーネントの役割、修正時の注意事項を明記。

# 資料作成オペレーション（AIとの制作フロー）

各コマのNotion講義資料を作成する際は、以下のステップで進めます。

### 1. 参照と要件確認
- `_lecture/docs/00_カリキュラム設計書.md` から、該当単元の「目標・扱う文法キーワード・プロパティ・演習課題」を確認する。
- `_lecture/docs/00_要件サマリー.md` のコーディングルール（FLOCSS、BEM、Dart Sass、アクセシビリティ等）を遵守する。

### 2. ファイルの作成と命名規則
- 作成先：`_lecture/` 直下
- 命名規則：`{2桁の単元番号}_{単元テーマ名}.md`
  - 例：`01_導入とGit環境.md`
  - 例：`02_BEMによるCSS設計.md`
- **下書き（draft）ファイルは作らず、直接このファイルをチャット上で推敲・更新していく**（バージョン管理はGitで行う）。

### 3. フォーマット・スタイルの統一
- **冒頭ナビゲーション**: 全単元へのリンク一覧（Notionのページリンク）
- **本日のゴール**: そのコマで達成する目標（箇条書き3〜5点）
- **解説ブロック**: 丁寧なたとえ話、コード例、良い例（Good）・悪い例（Bad）の比較
- **Notionコールアウト風の補足**: `<aside> 💡 ... </aside>` による現場の実務ノウハウやTips
- **体験・演習（ハンズオン）**: 学生が実際にコードを書いてブラウザで確認するステップ形式
- **まとめ & 次回予告**: 学習の振り返りと次単元への接続

# 年度更新オペレーション（次年度への移行）

2026年度の授業が完了し、次年度（2027年度）の教材作成を開始する際は、以下の手順で一括アーカイブします。

1. `_lecture/` の中身（講義資料テキストおよびdocs）を、そのまま `_backup/2026-lecture/markup-advanced/` に移動する。
2. 新たな `_lecture/` ディレクトリを作成し、新年度のカリキュラム作成を開始する。
これにより、常に「現役の最新講義データは `_lecture/` にある」状態を維持できます。
