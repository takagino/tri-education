### 単元2: CSS設計の必要性とBEMの基本・実践（第2週：コマ4〜6）
> **目標**: スタイルの衝突や詳細度競合（CSSが破綻する原因）を理解し、BEM（Block, Element, Modifier）の概念とMindBEMding記法を習得して、単一パーツから複合UIまで破綻なくマークアップできる。

- **概念・キーワード**:
  - なぜCSSは破綻するのか？（グローバルスコープ、セレクタ詳細度、意図しない上書き）
  - 優れたCSS設計の4原則（予測しやすい、再利用しやすい、保守しやすい、拡張しやすい）
  - BEMの思想:
    - **Block**: 独立した再利用可能なコンポーネント（例: `.card`, `.button`）
    - **Element**: Blockを構成する要素（例: `.card__title`, `.card__img`）※アンダースコア2つ
    - **Modifier**: 状態やバリエーション（例: `.button--primary`, `.button--large`）※ハイフン2つ
  - 状態クラス: `.is-active`, `.is-open` の役割
  - MindBEMding記法
  - コンポーネント指向のマークアップとBlock内のBlock配置
  - Elementの深さ制限の原則（`.block__elem1__elem2` はアンチパターン。常にフラットに保つ）
- **演習課題・作例**:
  - **`02-roysha-bem` / `03-newslly-bem`**: 用意されたデザインパーツ（カードUI、バナー、ボタン等）および複数セクションに対し、BEMに準拠したHTMLマークアップとCSSを記述・検証する

### 単元3: Sass（SCSS）の基礎とモジュール分割（第3週：コマ7〜9）
> **目標**: CSSプリプロセッサ（Sass）のメリットを理解し、変数、ネスト、アンダースコア付きパーシャルファイル分割（`_partial.scss`）と `@use` によるモジュール管理、`@mixin` の基礎を習得して、既存CSSをSCSSにリファクタリングできる。

- **概念・キーワード**:
  - CSSプリプロセッサとは（CSSの記述効率・保守性向上の仕組み）
  - SCSS構文（CSS互換の書き方）
  - 変数（Variables）: `$color-primary`, `$font-base`
  - ネスト（入れ子）: 親セレクタ参照アンパサンド（`&`）を用いた擬似クラスやBEM Element/Modifierの結合
  - ネストの階層制限（原則3階層まで）
  - パーシャル（`_filename.scss`）とコンパイル対象ファイル（`style.scss`）の区別
  - Modern Sass: `@use` によるモジュール読み込み（`@use 'variables' as *;`）※旧 `@import` の非推奨理由
  - `@mixin` と `@include`（スタイルの共通化と再利用の基本）
- **演習課題・作例**:
  - **`04-newslly-sass`**: BEMで書いた既存CSSを、Sassの変数・ネスト・パーシャルファイル分割・Mixinを用いてリファクタリングする

### 単元4: モダンなCSS単位とカスタムプロパティ（第4週：コマ10〜12）
> **目標**: 固定値（px）依存から脱却し、ルート基準の相対単位（rem）とCSSカスタムプロパティ（ネイティブ変数）を使いこなして、スケーラブルで柔軟なUIを構築できる。

- **概念・キーワード**:
  - 相対単位の特性: `rem`（Root em）, `em`, `%`, `vw`, `vh`, `svh` / `dvh` / `lvh`（スマホ動的ビューポート）
  - rem設計の基礎: ルートフォントサイズ（`html { font-size: 62.5%; }` ＝ 10px換算、またはブラウザ標準16px基準）
  - ユーザーのブラウザ設定（文字サイズ変更）を尊重するアクセシビリティ観点
  - CSSカスタムプロパティ（CSS変数: `--main-color: #333;`）と `var()` 関数
  - Sass変数（ビルド時に静的解決） vs CSSカスタムプロパティ（実行時に動的変更可能）の使い分け
  - CSS変数を用いたカラーテーマ切り替え（ライトモード / ダークモード）
- **演習課題・作例**:
  - **`08-cubehaus-rem` / `09-mache-rem`**: pxで組まれたコードをrem設計に書き換え、CSSカスタムプロパティによるテーマ切り替えボタンを実装する

### 単元5: モダン・レスポンシブWebデザインとFluid Layout（第5週：コマ13〜15）

- **概念・キーワード**:
  - モバイルファースト設計の思考法

    - `clamp(最小値, 推奨可変値, 最大値)`: 画面幅に応じて滑らかに変化するフォントサイズ・余白
    - `min()`, `max()`
  - Fluid Typography（流体タイポグラフィ）の計算ロジック
  - `aspect-ratio` プロパティ（paddingハックに代わるアスペクト比維持）
- **演習課題・作例**:

### 単元6: FLOCSSアーキテクチャの概念とディレクトリ設計（第8週：コマ22〜24）
> **目標**: 中間課題で直面したファイルの肥大化や命名の迷いを解消するため、現場標準アーキテクチャ「FLOCSS」の3層構造（Foundation, Layout, Object）とディレクトリ設計を習得する。

- **概念・キーワード**:
  - なぜ大規模・長期運用にCSSアーキテクチャが必要なのか（中間課題の振り返り）
  - FLOCSS（Front-end Language Organized Cascading Style Sheets）の概念:
    - **Foundation**: リセットCSS、全体設定、変数、Mixin（中間課題で学んだrem設定やmqを配置）
    - **Layout**: サイト共通の大枠レイアウト（ヘッダー、メイン、フッター等。接頭辞 `l-`）
    - **Object**: サイトを構成するすべてのUI（接頭辞 `c-`, `p-`, `u-`）
      - Component: 汎用・再利用可能な小さなUIパーツ（接頭辞 `c-`）
      - Project: 固有の文脈を持つ複合UIパターン（接頭辞 `p-`）
      - Utility: 唯一のスタイルを適用するヘルパー（接頭辞 `u-`）
- **演習課題・作例**:
  - **`05-smartspace-sass`**: FLOCSSのディレクトリ構成を作成し、Foundation（変数・リセット）とLayout、Objectフォルダを立ち上げて基本スタイルを定義する

### 単元8: 2次元レイアウト革命：CSS Gridとsubgrid（第10週：コマ28〜30）
> **目標**: Flexbox（1次元）とCSS Grid（2次元）の本質的な違いを理解し、複雑なグリッドシステム、`minmax()` や `auto-fit` による自動折り返し、`subgrid` による子要素の高さ同期を実装できる。

- **概念・キーワード**:
  - Flexbox（行または列の1次元） vs CSS Grid（行と列の2次元）の使い分け
  - GridコンテナとGridアイテム
  - `grid-template-columns`, `grid-template-rows`, `fr`（Fraction）単位
  - `gap`（行間・列間余白）
  - `grid-template-areas` による直感的なエリア配置
  - メディアクエリなしの自動折り返し: `repeat(auto-fit, minmax(280px, 1fr))`
  - `subgrid`: 親のグリッドトラックを子・孫要素に継承させ、カードUIのタイトル行やボタン位置の高さを完全同期するモダン手法
- **演習課題・作例**:
  - 非対称グリッドギャラリー（雑誌風のレイアウト）
  - subgridを用いたカードコンポーネント（タイトル文字数に関わらず行高が綺麗に揃うUI）

### 単元9: WebサイトパフォーマンスとCore Web Vitals（第11週：コマ31〜33）
> **目標**: 表示速度がビジネスやSEOに与える影響を理解し、GoogleのCore Web Vitalsの重要指標を把握した上で、Lighthouseを用いた計測と具体的な画像・リソース最適化ができる。

- **概念・キーワード**:
  - パフォーマンスが離脱率やコンバージョンに与える影響
  - Core Web Vitalsの重要指標:
    - **LCP (Largest Contentful Paint)**: 最大コンテンツの表示時間
    - **CLS (Cumulative Layout Shift)**: 視覚的なレイアウトのズレ
    - **INP (Interaction to Next Paint)**: 操作への応答性
  - Google Lighthouseを用いた品質測定とスコアの見方
  - 画像の最適化:
    - 次世代画像フォーマット（WebP, AVIF）
    - `<picture>` 要素と `<source type="image/webp">`
    - `srcset` と `sizes` 属性（解像度・画面幅に応じた画像切り替え）
    - `loading="lazy"`（遅延読み込み）
    - `decoding="async"`, `fetchpriority="high"`（LCP要素の優先読み込み）
  - 画像の幅・高さ明記（`width`, `height` 属性によるCLS防止）
- **演習課題・作例**:
  - 意図的に巨大なPNG/JPEGを多用した重いWebサイトを題材に、Lighthouseで現状を計測し、画像フォーマット変換・Lazy Load・アスペクト比指定を行ってスコアを劇的に改善するワーク

### 単元10: Webアクセシビリティ（a11y）とセマンティクス（第12週：コマ34〜36）
> **目標**: 障害者や高齢者だけでなくすべてのユーザーに届くWebアクセシビリティの重要性を理解し、セマンティックなHTML、適切なコントラスト、キーボード操作配慮、WAI-ARIAの基礎を実装できる。

- **概念・キーワード**:
  - Webアクセシビリティ（a11y）とは（誰一人取り残さないWeb設計）
  - マシンリーダビリティとSEOへの好影響
  - 適切なセマンティックタグの選定:
    - ランドマーク要素: `<header>`, `<nav>`, `<main>`, `<article>`, `<section>`, `<aside>`, `<footer>`
    - 見出し階層（`<h1>`〜`<h6>` のスキップ禁止ルール）
  - 画像の代替テキスト（`alt` 属性の適切な使い分け: 情報画像 vs 装飾画像）
  - 視覚アクセシビリティ: カラーコントラスト比（WCAG AA基準: 通常テキスト4.5:1以上）
  - キーボード操作対応:
    - Tabキーによるフォーカス移動
    - `:focus-visible` による明瞭なフォーカスリング表示
  - WAI-ARIAの基本役割: `aria-label`, `aria-hidden="true"`, `aria-expanded`
- **演習課題・作例**:
  - **`accessibility/bad.html` から `good.html` への改修演習**:
    - すべて `<div>` で書かれたコードを適切なセマンティックタグに修正
    - コントラスト比不足の解消、キーボード操作で操作できるボタンへの変更
    - アクセシビリティ検証ツール（Lighthouse, axe DevTools）による合格判定

### 単元11: GSAPによるWebアニメーションの基礎（第13週：コマ37〜39）
> **目標**: CSSアニメーションとJavaScriptアニメーションライブラリ（GSAP）の特性を理解し、CDN導入からTween（単一アニメーション）、タイムライン（連続アニメーション）、マイクロインタラクションを実装できる。

- **概念・キーワード**:
  - CSSアニメーション（`transition`, `@keyframes`）の限界とJSライブラリの強み
  - GSAP 3（GreenSock Animation Platform）の導入（CDN / scriptタグ）
  - 基本構文:
    - `gsap.to(target, { vars })`: 現在の状態から指定値へ
    - `gsap.from(target, { vars })`: 指定値から初期状態へ（画面イン演出に最適）
    - `gsap.fromTo(target, { fromVars }, { toVars })`
  - 主要プロパティ: `x`, `y`, `scale`, `rotation`, `opacity`, `duration`, `delay`, `ease`, `stagger`（時間差アニメーション）
  - イージングの心地よさ（`power2.out`, `back.out(1.7)` 等）
  - `gsap.timeline()`: 連続するアニメーションのタイムライン制御
- **演習課題・作例**:
  - カードUIのホバーマイクロインタラクション
  - ページ読み込み時にヘッダー、タイトル、ボタンが順番にテンポよく現れるヒーローセクション演出

### 単元12: ScrollTriggerによるスクロール連動演出（第14週：コマ40〜42）
> **目標**: GSAP公式プラグイン「ScrollTrigger」の仕組みを理解し、要素が画面内に入ったときのトリガー発火、スクロール量に連動したパララックス効果（`scrub`）、ピン留め演出を実装できる。

- **概念・キーワード**:
  - `gsap.registerPlugin(ScrollTrigger)`
  - ScrollTriggerの基本オプション:
    - `trigger`: 監視対象要素
    - `start`: 開始位置（例: `'top 80%'`）
    - `end`: 終了位置（例: `'bottom 20%'`）
    - `markers: true`: 開発用デバッグガイド表示
    - `toggleActions`: 進入時・通過時・戻り時の動作指定
  - `scrub`: スクロール量に完全同期するアニメーション
  - `pin: true`: 要素を画面内に固定してスクロール演出を行うテクニック
  - 視差効果（パララックス）の基本実装
  - やりすぎない上品なWeb演出の設計思想
- **演習課題・作例**:
  - スクロールに合わせて写真がふわりと浮かび上がるフェードイン演出
  - スクロール量に応じて背景写真がゆっくり動くパララックスセクション
  - 固定（Pin）されたタイトルエリアの前をコンテンツが通り過ぎるモダンなLP演出
