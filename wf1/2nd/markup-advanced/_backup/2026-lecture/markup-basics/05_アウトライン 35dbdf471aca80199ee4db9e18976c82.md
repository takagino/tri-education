# **3. 構造化のための要素**

以前、要素をグループ化するための要素「div」を勉強したが、

- マークアップの効率向上のための「div」
- デザイン上どうしてもグループ化しないといけない「div」
- 全体の構造をわかりやすくするための「div」

など、様々な用途の「div」が混在すると、HTML全体の見通しが悪くなる。

そこで、HTMLバージョン5から、**構造化**をするための要素が多数追加された。

**【構造化とは？】**

物事の全体を定義した上で「構成要素」と「構成要素間の関係」を整理する取り組みを指す。

---

## **3-1. Webサイトの構成例**

Webページは基本的に以下の図のようなレイアウトで構成されている。

![01.png](05_%E3%82%A2%E3%82%A6%E3%83%88%E3%83%A9%E3%82%A4%E3%83%B3/01.png)

**【header（ヘッダー）】**

- サイトのメインタイトルやロゴ
- グルーバルナビゲーション（各ページへのリンク）
- 主要ベージへのリンク
- ページ内検索フォーム　など、全ページにわたって表示したい内容

**【main（メインコンテンツ）】**

- ページの内容

**【footer（フッター）】**

- サイトマップ
- 住所などの基本情報
- 著作権に関する情報　など、全ページにわたって表示したい内容

---

## **3-2. 全体を構造化するための要素**

HTMLバージョン5より、レイアウトの構成を指定するため、その名前通りの要素が追加された。

```jsx
<!doctype html>
<html lang="ja">
	<head>
		<meta charset="utf-8">
		<title>education</title>
		<link rel="stylesheet" href="./style.css">
	</head>
	<body>
		<header>
		</header>
		
		<main>
		</main>
		
		<footer>
		</footer>
	</body>
</html>
```

---

## **3-2. 文書内容を構造化するための要素**

HTMLバージョン5より、文書内容の構造を指定するための要素が追加された。これらをまとめて「**セクショニング・コンテンツ**」と呼ぶ。

**section（セクション）要素**

HTML文書の中で、意味的に関連するグループを表す。

セクションを表現するより意味的に具体的な要素がない場合に使用する。

必ずではないが、通常はセクションには見出しがある。

**article（アーティクル）要素**

一つの自己完結型のコンテンツ（例えば、雑誌や新聞の記事、ブログの記事）を表す。

必ずではないが、通常はアーティクルには見出しがある。

※RSSリーダーなどに「サイトの更新情報」として発信してもおかしくないような箇所。

**aside（アサイド）要素**

文書のメインコンテンツと間接的な関係しか持っていない部分（例えば、バナー広告、関連記事、コラム）を表す。

※ブラウザの機能などで非表示にされても問題ないような箇所。

**nav（ナビ）要素**

文書内の主要なナビゲーションを表す。

<aside>
💡

これらは一般的なWeb標準（セマンティクス）の基準です。実際の制作現場では企業ごとに独自のコーディング規約が存在するため、実務においては所属チームのルールを最優先してください。

</aside>

そして、「セクショニング・コンテンツ」は文書の構造を指定すると同時に「**アウトライン**」を明確に形作るために使用される。

## **4-2. 補足「画像の代替テキスト」**

代替テキストはWebサイト内に含まれている画像や動画が何らかの原因で表示されなかったときや、視覚障害者などが音声ブラウザを使用するときに替わりに表示するテキストを指す。

**【alt（オルト）属性】**

```markup
<img src="./images/img_logo.png" alt="hotelin">
```

<aside>
⚠️

特に代替テキストが必要ない画像でも、alt属性を追加し、値を空にしておくこと！

※画像にalt属性が無いと文法的にエラーとなります。
 ※「alt属性」の値を空にしておくと、音声ブラウザなどで読み飛ばしてくれるため、アクセシビリティが向上します。

</aside>

---

## **4-3. 暗黙的アウトラインの破綻**

かつてのWebページは、本や論文のような「上から下へ一直線に読む」シンプルな文書でした。そのため、見出し（h1〜h6）の順番を守るだけで綺麗な階層（暗黙的アウトライン）が作れました。

しかし、現代のWebサイトのような複雑化したレイアウトにおいて、「見出しの順番」だけで全体の構造を表現することには限界が来ました。

**【複雑化による問題点】**

- 直線的な見出しのルールだけでは、どこからどこまでが「1つのグループ」なのか、機械（検索エンジンや音声ブラウザ）に正確に伝わらない。
- 無理やりグループ分けをするために、意味を持たない「div要素」が乱用され、HTMLが複雑で解読不能になった。
- 共通のパーツ（記事一覧など）を別のページで使い回す際、ページごとに見出しのレベル（h2やh3など）をいちいち書き換えないと、アウトラインが崩れてしまう。

これらの問題を解決するため、「ここからここまでが独立した記事」「ここは補足情報」と、ブロックごとに明確な意味（明示的アウトライン）を持たせて整理整頓する section や article などの「セクショニング・コンテンツ」が誕生しました。

## **4-5. セクショニング・ルート**

セクショニングルートは、それ自体が独自のアウトラインを形成する要素で、文書全体のアウトラインには影響を与えない。

**【body要素】**

一番最初にアウトラインを生成し、最初に出てきた「子要素の見出し」をラベルとする。

```markup
<body>
	<header>
		<h1>セクショニングルート</h1>
	</header>
	
	<main>
		<section>
			<h2>見出し2</h2>
			
			<section>
				<h3>見出し3</h3>
			</section>
			<section>
				<h3>見出し3</h3>
			</section>
		</section>
		
		<section>
			<h2>見出し2</h2>
		</section>
	</main>
	
	<footer>
	</footer>
</body>
```

![SCR-20260512-budt.png](05_%E3%82%A2%E3%82%A6%E3%83%88%E3%83%A9%E3%82%A4%E3%83%B3/SCR-20260512-budt.png)

<aside>
💡

ページ全体の大見出しである「h1」は基本ヘッダーの中に書くが、bodyはセクショニングルートなので、section等で囲む必要はない。

</aside>

**【blockquote要素】**

「引用」を表す「blockquote要素」などは、見出しがあってもアウトラインには表示されない。

```markup
<body>
	<header>
		<h1>セクショニングルート</h1>
	</header>
	
	<main>
		<section>
			<h2>見出し2</h2>
			
			<section>
				<h3>見出し3</h3>
			</section>
			<section>
				<h3>見出し3</h3>
				
				<!-- 引用文を追加 -->
				<blockquote>
			    <h1>引用内の見出し1</h1>
			  </blockquote>
			</section>
		</section>
		
		<section>
			<h2>見出し2</h2>
		</section>
	</main>
	
	<footer>
	</footer>
</body>
```

## **4-6. アウトラインの必要性**

**【作る側にとって】**

- アウトラインを意識してマークアップすることで、自然と綺麗なソースコードになる。
- 同じアウトライン、同じルールでマークアップをすれば、チームメンバー全員が理解できる。
- 結果、作業スピードがあがる。

**【見る側にとって】**

- スクリーンリーダー（音声読み上げソフト）は、見出しの階層やセクション情報を元にページを読み上げる。
- 結果、視覚障害を持つ方などが情報を素早く正確に取得することができる。

**【機械にとって】**

- Googleの検索エンジンは、適切な見出し構造とセクショニング・コンテンツからページの内容や重要度を正確に読み取る。
- 結果、検索結果の上位に表示され、多くの人に情報を届けることができる。

# 5. ここまでのまとめ「マークアップの手順とコツ」

## 5-1. デザインデータを見ながら「構造」と「役割」を考える

1. 画像となる部分、リンクがついている部分はどこか？（img要素やa要素を使う部分を把握）
2. 全体の構造はどうなっているか？（header要素、main要素、footer要素）
3. アウトライン（文章構造）はどうなっているか？（section要素・article要素で内容を分ける、1つ以内の見出しを設定する）
    - 見出しはレベルの順番に気を付ける（h1 → h2 → h3）
    - h1はページに1つだけ
    - 基本は「section要素」、記事のような独立したコンテンツの場合は「article要素」

---

## 5-2. 一番多いであろう本文のCSSをbody要素に設定

```css
@charset "utf-8";

body{
	margin: 0;
	color: #000000;
	font-size: 16px;
	font-family: Arial, Helvetica, sans-serif; /* ヒントを使用（優先順位のみ変更）*/
	line-height: 1.5; /* 行の高さ ÷ フォントサイズ（単位はなし） */
	letter-spacing: 0.05em; /* 文字間 ÷ 1000（単位はem） */
}
```

---

## 5-3. 「大きい→細かい」の順番にマークアップ

1. 全体を中央寄せにするwrapperを設定。
    
    ```markup
    <div class="wrapper">
      ...
    </div>
    ```
    
    ```css
    .wrapper {
        width: 750px; /* デザインデータのガイドからガイドまでの長さを測る */
        margin-left: auto;
        margin-right: auto;
    }
    ```
    
2. header要素、main要素、footer要素のボックスモデルと共通のプロパティから設定していく。
    - ボックスモデルは「width」「height（しばらくは使用しない）」「padding」「border」「margin」
    - 共通のプロパティは「text-align」など
    - 要素の追加・削除が発生しても、極力コードの修正がないようにする
    
3. section要素、article要素、div要素には原則class名をつけ、ボックスモデルと共通のプロパティから設定していく。
    - class名は「その要素の内容や役割」がわかるものにする
    
    ```markup
    <section class="news">
      <div class="post">...</div>
    </section>
    ```
    

---

## 5-4. ひとつひとつの要素を微調整

1. 同じ見た目の要素には同じclass名を使いまわす。
2. スタイルの継承（親子関係）や子孫セレクタをうまく使うことで、少ないコードでCSSを設定していく。
    
    ```css
    .news .post {
        margin-bottom: 40px;
        padding-bottom: 40px;
        border-bottom: 1px dotted #898989;
    }
    
    .trending .post {
        background-color: #F6F6F6;
    }
    ```
    
3. marginの相殺が起きることに注意。

## 5-5. 全体を通じて意識すること

- HTMLの役割は「構造化」、CSSの役割は「見た目の整形」
- デザイン通りに組むのではなく、「意味を持ってマークアップする（意図を説明できる）」ことが大切
- 書く順番は「大きい構造 → 小さな要素 → 細かい装飾」
- class名は未来の自分が読んでもわかる名前に
