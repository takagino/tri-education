# 3. スマホ対応の方法

## 3-1. 個別URLでモバイル用サイトを構築

**【参考例】**

[Yahoo! JAPAN](https://m.yahoo.co.jp/)

**【メリット】**

- スマホで閲覧することに特化したWebサイトを構築できる。
- 軽量化しやすく、読み込み速度をコントロールしやすい。
- 古いブラウザを考慮する必要がないため、HTML5やCSS3などの最新技術をふんだんに使うことができる。

**【デメリット】**

- サイト構成が分断され、メンテナンスや更新工数が増加。
- URLごとにSEO対策が必要。
- ユーザーが指し示すURLが分離しているため、ブランディングの統一に課題。

---

## 3-2. 端末ごとにファイルを振り分ける（動的サービング）

**【参考例】**

[Amazon.co.jp | Books, Apparel, Electronics, Groceries & more](https://www.amazon.co.jp/)

[【楽天市場】Shopping is Entertainment! ： インターネット最大級の通信販売、通販オンラインショッピングコミュニティ](https://www.rakuten.co.jp/)

**【メリット】**

- スマホで閲覧することに特化したWebサイトを構築できる。
- HTML/CSSの内容を端末に応じて最適化できる。
- URLは統一され、ブックマークや共有がシンプル。

**【デメリット】**

- サーバー側で端末の判定とコンテンツ分岐が必要で設計・実装が複雑。
- 判定エラーによる誤配信リスクがある。
- 高度な知識が必要。

---

## 3-3. **レスポンシブウェブデザイン**

**【参考例】**

[Responsive Web Design JP | 日本国内の秀逸なレスポンシブWebデザインを集めたギャラリーサイト](https://responsive-jp.com/)

**【メリット】**

- コード・URLが統一され、管理・保守が効率的。
- SEO効果は最も高く、Google公式にも“推奨”されている。
- デザインやレイアウトの一貫性が保たれる。

**【デメリット】**

- 初期設計やCSS/JSの細かい制御が必要で、構築難易度が高め。
- モバイル専用に軽量化しにくく、不必要なロードが発生する場合がある。

---

## 3-4. 比較まとめ

| **手法** | **URL構成** | **メンテナンス性** | **SEO** | **表示スピード・操作性** | **実装の難易度** |
| --- | --- | --- | --- | --- | --- |
| 個別URLサイト | 分離（例：m.example.com） | △（二重管理） | △（別途設定必要） | ◎（専用設計可） | 中〜高 |
| 動的サービング | 同一URL | ○（統一管理） | ◎（設定が簡素） | ◎（端末最適化可） | 高（判定ロジック要） |
| レスポンシブ | 同一URL | ◎（一元管理） | ◎（Google推奨） | ○（調整次第で高） | 中〜高（CSS設計要） |

# 5. **レスポンシブウェブデザインの基本**

**【5つのポイント】**

- Fluid Layout（フルードレイアウト）
- Fluid Image（フルードイメージ）
- Media query（メディアクエリ）
- Breakpoint（ブレイクポイント）
- Viewport（ビューポート）

---

## 5-1. **Fluid Layout（フルードレイアウト）**

Webページのレイアウトは大きく分けると2種類ある。

- **Fixed Layout（フィックスドレイアウト）：**width, margin, padding を絶対単位の px で指定する。（今まではこちら）
    
    ![fluid-sample4.jpg](10_%E3%82%B9%E3%83%9E%E3%83%9B%E5%AF%BE%E5%BF%9C/fluid-sample4.jpg)
    
- **Fluid Layout（フルードレイアウト）：**width, margin, padding を相対単位の % や em、fr などで指定する。
    
    ![fluid-sample5.jpg](10_%E3%82%B9%E3%83%9E%E3%83%9B%E5%AF%BE%E5%BF%9C/fluid-sample5.jpg)
    

**【.innerの基本形】**

```css
.inner {
  width: 87.5%; /* スマホ版のコンテンツ幅と余白の割合 */
  max-width: 800px; /* デスクトップ版のコンテンツ幅 */
  margin-left: auto;
  margin-right: auto;
}
```

**【固定（px）から可変（%）へ変換】**

変換したい値（要素や余白の幅）÷ 変換したい値の親要素の幅 x 100

例） (380 / 800) * 100 = 47.5%

**max-width**

要素の最大幅を設定する。（これ以上は大きくならない）

[max-width - CSS | MDN](https://developer.mozilla.org/ja/docs/Web/CSS/Reference/Properties/max-width)

---

## 5-2. **Fluid Image（フルードイメージ）**

```css
img {
  max-width: 100%; /* ←修正：要素が親要素の幅を超えないようにする */
  height: auto;
  vertical-align: middle;
}
```

※「リセットcss」に書いてあることが多いが、念のために自分でも書いておくこと。

---

## 5-3. Media query（メディアクエリ）

画面サイズや解像度などの閲覧環境に応じて適用するスタイルを切り替えられる機能。

```css
/* 共通のスタイル */
body{
  background-color: #fff;
}

/* ウィンドウサイズが600px〜800pxの時 */
@media (600px <= width <= 800px) {
  body{
    background-color: #f00;
  }
}

/* ウィンドウサイズが800pxより大きい時 */
@media (800px < width) {
  body{
    background-color: #00f;
  }
}
```

<aside>
💡

**メディアクエリの昔の書き方**

先ほど説明した `@media (640px <= width)` は、最新の直感的な書き方です。しかし、少し前に作られたWebサイトや、ネット上の古い記事では以下のように書かれていることが多くあります。

```css
/* 昔の書き方（現在でもよく見かけます） */
@media (min-width: 640px) { ... }
```

どちらも「640px以上の時」という意味です。現場に出た時に戸惑わないよう、両方の書き方があることを知っておきましょう！

</aside>

**【メディアクエリを書く順番】**

```css
/* モバイルファースト（モバイル版を先にマークアップする）
-----------------------------------*/
body{ background-color: #fff; }

/* ウィンドウサイズが600pxより大きい時 */
@media (600px < width) {
  body{ background-color: #f00; }
}

/* ウィンドウサイズが960pxより大きい時 */
@media (960px < width) {
  body{ background-color: #00f; }
}

/* デスクトップファースト（デスクトップ版を先にマークアップ）
-----------------------------------*/
body{ background-color: #fff; }

/* ウィンドウサイズが960pxより小さい時 */
@media (width < 960px) {
  body{ background-color: #f00; }
}

/* ウィンドウサイズが600pxより小さい時 */
@media (width < 600px) {
  body{ background-color: #00f; }
}
```

※ 授業では「**モバイルファースト**」でマークアップしていきます。

---

## **5-4. Breakpoint（ブレイクポイント）**

「960px」や「600px」など、メディアクエリでそれぞれ指定している画面幅のことを「ブレイクポイント」という。

新しいデバイス、またそれに対応したディスプレイサイズが次々に出てくるため、どのタイミングで切り替えればより多くのデバイスでレイアウトを崩さずに表示できるかを考える上で、「ブレイクポイント」はとても重要になる。

[【2026年版】レスポンシブデザインの教科書｜メリット・デメリットと失敗しない構築手順](https://shwat.jp/ultra/responsive-design/#index_id10)

★「ブレイクポイント 2026」で検索してみる。

---

## **5-5. Viewport（ビューポート）**

ブラウザに認識して欲しい表示領域の大きさを指定する。

[HTML <meta name="viewport"> 属性値 - HTML | MDN](https://developer.mozilla.org/ja/docs/Web/HTML/Reference/Elements/meta/name/viewport)

**【最低限の記述】**

```markup
<meta name="viewport" content="width=device-width, initial-scale=1.0">
```
