## 2. 科目のねらい & 技術選定の背景

### 2-1. 科目のねらいとコンセプト

### 2-2. 技術選定の理由と教育的意図

#### ① Three.js（3D）を除外した理由
- **学習コストの適正化**: 3Dグラフィックス（ポリゴン・3次元座標・カメラ・ライティング・行列変換）の概念習得には最低3〜4回の講義が必要であり、初学者にとってハードルが高く消化不良を起こすリスクがあります。
- **最終制作の完成度最大化**: 2Dのジェネラティブアート（p5.js）、スプライトアニメーション/ゲーム（p5play）、音響表現（p5.sound / Strudel）にフォーカスすることで、デザイン学科の学生が強み（イラスト・世界観設計・UI）を存分に発揮でき、最終課題の制作・調整期間を5回分（展示含む）しっかり確保できます。

#### ② Tone.jsではなく「p5.sound ＋ Strudel」を採用した理由
- **クラス設計の流用性（教育的効果）**: 単元4で学んだJavaScriptのクラス構造（`Orb`, `Ripple`, `WaveLine`）を壊すことなく、周波数解析（`p5.FFT`）の低音・中音・高音エネルギーを流し込むだけで瞬時にオーディオビジュアルへと昇華できます。
- **コードで音楽を創る体験**: 最先端のライブコーディング環境 [Strudel](https://strudel.cc/) を取り入れることで、音源を用意するだけでなく「自分でプログラミングしてビートやメロディを作る楽しさ」を体験し、自作音楽と自作アートの完全同期を実現します。

#### ③ スプライト・ゲーム表現に「p5play」を採用した理由
- **「抽象」から「具象」への自然なステップアップ**: 前半の幾何学図形や光の演出（抽象アート）でデータパイプラインを固めた後、後半はスプライトや物理演算を使ったキャラクター・ゲーム表現（具象アート）へ進むことで、受講者が飽きずに表現の幅を広げられます。
- **最終課題での多彩な選択肢**: 学生が「① オーディオビジュアル / VJ派」「② キャラクター / アニメーション派」「③ フィジカルゲーム派」のいずれかから、自分の最も得意な武器を選んで勝負できます。

#### ④ センサー入力値の調整における「二重構造」
- 生データのノイズや激しい揺らぎを抑えるため、**「Arduino側（ハードウェア近傍）」** と **「JavaScript側（表現近傍）」** の両面でデータ加工を徹底します。
  - **Arduino側**: `constrain()` による外れ値カット、`map()` によるスケーリング、指数平滑（RCフィルタ）によるゆらぎ除去。
  - **JavaScript側**: `0.0〜1.0` への正規化（Normalize）、線形補間（Lerp）による滑らかなイージング・加減速処理。

## 5. 各単元詳細（第1回〜第15回）

---

### 第1回: 単元1: Arduinoの基礎とWeb Serial API入門（実施済）
> **目標**: Arduino Nano R4の基本構造と開発環境を理解し、ブレッドボードでの基本回路（LED・スイッチ・センサー）の構築、およびWeb Serial APIを用いたブラウザ連携の基本手順を体験する。

- **内容振り返り**:
  - Arduino IDE 2.xのセットアップとLチカ（Blink）
  - 回路の基本原則（5V → 負荷 → GND）
  - 距離センサー（GP2Y0A21YK）のアナログ値読取（`analogRead`）とシリアルモニタ出力
  - Web Serial API経由でブラウザ上のHTML要素（緑のbox）の拡大縮小（`scale`）を制御

---

### 第2回: 単元2: センサー入力値の調整とフィジカルギミック（実施済）
> **目標**: スイッチによるデジタル制御、距離センサー（復習）および明るさセンサー（CdSセル・分圧回路）のアナログ入力を扱い、センサー生データの課題（ノイズ・揺らぎ）を軽減するアルゴリズム（指数平滑）や値の整形（`constrain`, `map`）を実践する。サーボモーターや振動モーターの出力を安定制御し、入力（スイッチ/距離/CdS）と出力（サーボ/振動）を組み合わせた「触って動く楽しいクラフト作品」を制作できる。また、次週以降のWeb表現につながる「正規化（0〜1）」「Lerp平滑化」の基礎概念を理解する。

- **主要内容**:
  - 明るさセンサー（CdSセル）の仕組みと10kΩ分圧回路の構築・読取
  - 生データの課題と加工: `constrain` による異常値カット、`map` によるサーボ角度（0〜180）への変換
  - ゆらぎの軽減: 指数平滑フィルタ（RCローパスフィルタ）の実装
  - 出力パーツの制御: サーボモーター（SG90）、振動モーター（PWM）
  - ミニ制作課題: 「触って動く楽しいクラフト作品」（イラストを貼ったサーボ/振動ギミック）

---

### 第3回: 単元3: p5.js 基礎（描画・色彩・運動の数理）（実施済）
> **目標**: クリエイティブコーディングライブラリ「p5.js」の描画構造（`setup`, `draw`）を理解し、数学（三角関数・乱数・ベクター）と色彩（HSB）を用いた動的なグラフィックを生成できる。

- **主要内容**:
  - p5.jsの基本サイクル: `setup()`（初期化）と `draw()`（60fpsループ構造）
  - 基本図形とスタイリング（`fill`, `stroke`, `strokeWeight`）
  - 色彩空間: HSBカラーモード（色相 Hue 0〜360度、彩度 Saturation、明度 Brightness）
  - 光の残像エフェクト: アルファ付き `background()` による軌跡描画
  - 運動の数理①: 三角関数（`sin` / `cos`）による周期振動・呼吸のような脈動・円運動
  - 座標変換: `push()` / `translate()` / `rotate()` / `pop()` による幾何学展開
  - 運動の数理②: 乱数（`random`）とパーリンノイズ（`noise`）による有機的な揺らぎ
- **演習課題**:
  - マウスや時間経過に応じて、有機的に形や色が変わるジェネラティブグラフィック作品の作成

### 第4回: 単元4: p5.js × センサー連携（ジェネラティブアートとクラス設計）（実施済）

## 7. トラブルシューティング & 指導ガイド

### 7-1. Web Serial API 特有のトラブルと回避策
1. **「ポートがビジーで開けない / Failed to open serial port」**:
   - **原因**: Arduino IDEの「シリアルモニタ」が開いたまま、あるいは別ブラウザタブで接続したままになっている。
   - **対処法**: Arduino IDEのシリアルモニタを「×」で閉じ、ブラウザの再読み込み（F5 / Cmd+R）を行う。
2. **「データが途切れる・NaNになる」**:
   - **原因**: シリアル通信はバイト単位で届くため、改行コード（`\n`）の途中で読み取ってしまうことがある。
   - **対処法**: `sensor.js` のようにバッファ変数を用意し、完全な1行が得られた場合のみ数値化する定型モジュールを徹底する。

### 7-2. p5.sound / Web Audio 特有のトラブルと回避策
1. **「The AudioContext was not allowed to start」**:
   - **原因**: ブラウザの自動再生ポリシー（Autoplay Policy）により、ユーザーのクリック等のジェスチャー前に音が鳴ろうとした。
   - **対処法**: `mousePressed()` やスタートボタンのクリックイベント内で `userStartAudio()` を呼び出す。
2. **「マイク入力が取得できない / 音量が0のまま」**:
   - **原因**: ブラウザのマイクアクセス許可がブロックされている、またはローカルファイル（`file://`）で実行している。
   - **対処法**: ローカルサーバー（Live Server等）経由で `http://localhost:...` で開き、ブラウザのアドレスバー左側の鍵アイコンからマイク権限を許可する。
