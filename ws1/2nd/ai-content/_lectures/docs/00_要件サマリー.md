## 3. 科目のねらいとコンセプト

### 「画面の中だけで完結しないフィジカルなモノづくり × Web表現技術」

Webブラウザはマウスやキーボード、タッチパネルだけで操作するものという固定観念を壊し、**「現実世界の物理的なアクション（触る・近づく・覆う・押す）」をセンサーで検知し、Webブラウザ上のリッチな「映像（アニメーション・アート）」と「音（インタラクティブサウンド）」へリアルタイムに変換する体験型コンテンツ**を制作します。

```mermaid
graph LR
    subgraph フィジカル世界（入力）
        A[手・身体・物体のアクション] --> B[センサー・スイッチ]
        B --> C[Arduino Nano R4]
    end

    subgraph 通信・データ処理
        C -->|Web Serial API| D[ブラウザ JavaScript]
        D --> E[正規化 0.0〜1.0 / 平滑化 Lerp / トリガー]
    end

    subgraph デジタル世界（出力・表現）
        E --> F[画像コマ送りアニメーション]
        E --> G[p5.js ジェネラティブアート]
        E --> H[Tone.js サウンド・シンセシス]
    end
```

## 5. 技術選定の理由と調整意図

### 1. Three.js（3D）を除外した理由
- **学習コストの適正化**: 3Dグラフィックス（ポリゴン・カメラ・ライティング・行列変換）の概念習得には最低3〜4回の講義が必要であり、初学者にとってハードルが高く消化不良を起こすリスクが高い。
- **最終制作の完成度最大化**: 2Dのコマ送りアニメーション、p5.jsのジェネラティブアート、Tone.jsのサウンド合成にフォーカスすることで、デザイン学科の学生が強み（イラスト・世界観設計・UI）を存分に発揮でき、最終課題の制作・調整期間を5回分（展示含む）しっかり確保できる。

### 2. アニメーションを「GSAP」ではなく「画像切り替え（フレームアニメーション）」にした理由
- **「Webサイト演出」から「コンテンツ制作」への転換**: GSAPはWebサイトのUIやスクロール演出に長けているが、本授業が目指すのは「触って遊べるインタラクティブコンテンツ」。
- **学生自身のクリエイティビティ直結**: 自分で描いたイラストや撮影した写真のコマ送り（手回しアニメーション／ゾートロープ／表情変化／走るキャラクター）をセンサーで直接操る体験は、「命を吹き込む感覚」が強く、学生の制作モチベーションを劇的に刺激する。
- **実装の明快さ**: 連番画像配列のインデックス参照やCanvas描画、CSS steps()による実装は、JavaScriptの配列と数学的マッピング（正規化値 × コマ数）の理解に直結する。

### 3. 第2回「出力値の調整」の改善理由とフィジカル課題
- **生データの課題解決**: センサー値のノイズや範囲のバラつきを抑えるための必須テクニックを習得。
- **データ最適化の二重構造**:
  - Arduino側: `constrain()` による範囲制限、`map()` によるスケーリング、指数平滑（RCフィルタ）によるゆらぎ軽減。
  - JavaScript側: `0.0〜1.0` への正規化（Normalize）、線形補間（Lerp: Linear Interpolation）による滑らかなイージング処理。
- **新センサー（CdSセル）の導入**: 光の強弱をアナログ電圧として読み取る回路（10kΩ分圧回路）とコードの習得。
- **第2回ミニ制作課題**: 入力（スイッチ / 距離 / CdS）× 出力（サーボモーター / 振動モーター）を用いた、触って動く楽しいクラフト作品制作（手書きイラストもOK）。画面内だけでなくフィジカルに動く楽しさを体感させる。

## 6. 課題と評価の設計

### 1. 段階的な課題構成
1. **第2回ミニ制作課題**: 入力（スイッチ/距離/CdS）× 出力（サーボ/振動モーター）を使った、触って動くクラフト作品。描画ソフトまたは「手書きのイラスト」をモーターに貼り付けて制作。
2. **中間課題（第9回〜第10回）**: 「センサー ＋ アニメーション/p5.js ＋ Tone.js」を組み合わせた、1画面完結のインタラクティブミニ作品。
3. **最終課題（第11回〜第15回）**: 
   - **テーマ**: 「思わず触りたくなる、体験型インタラクティブ作品」
   - **想定シーン**: 学校のオープンキャンパス・募集イベントで、高校生や来場者が操作説明なしで直感的に楽しむ展示ブース。
   - **要件**:
     - Arduino（センサー・スイッチ）による物理入力。
     - Web Serial API経由でのブラウザ連携。
     - 視覚表現（コマ送りアニメーションまたはp5.js）＋ 聴覚表現（Tone.js）。
     - 物理的な外装・筐体（クラフト、ダンボール、アクリル等）の制作。
     - 無人でも復帰できるリセット処理・フェイルセーフ。

### 2. 成績評価配分（シラバス準拠）
- **課題作品の完成度と独創性（40%）**: 中間課題（15%）＋ 最終課題（25%）。技術的要件、クラフト性、触りたくなるUI/UX、演出のクオリティ。
- **基礎理解度（30%）**: センサー回路の理解、Web Serial通信、正規化・Lerp、各ライブラリの文法構造の理解。
- **授業への取り組み姿勢・AI活用度（30%）**: 演習での試行錯誤、生成AIをパートナーとした主体的なエラー解決、展示会でのプレゼン・相互フィードバックの積極性。
